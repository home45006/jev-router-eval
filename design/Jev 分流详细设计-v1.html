01本次要定的事

第 14 版的 Jev 只判一件事：交给快思考（NLU）还是交给 Agent 大脑。v5 架构把去向改成四个，本设计要把这四个去向落成可实现、可评测的规则。

变化第 14 版（现状）本设计（v5）
去向快思考 / Agent 大脑，两个NLU 直达 Agent 直达 慢思考 闲聊，四个。前两个合称快思考
Agent 直达没有。联网搜索、用车手册都要先进大脑，由大脑判出标签再调用单轮、只需一个 Agent 一次答完的请求，由 Jev 直接给出 agent_label，跳过大脑规划
慢思考的范围“快思考接不住的”都给大脑，范围很宽（闲聊、天气、找歌都进大脑）只收 NLU3.0 接不住、也不是单个 Agent 能直达的请求：跨多个能力、彼此有依赖的多步任务，以及 NLU3.0 接不住的句子（条件任务、长期规则、行程、记忆调用都改由对应 Agent 直达）
Jev 的问题is_fast、needs_rewrite 加两道 shadow 纠错题，都是 Noulis_unsafe、route、domain、agent_label、needs_context、has_nickname、segment_role[i]，一次请求并行判定
NLU现有 NLU 落域NLU3.0 大模型（清单 v13，45 域，其中 19 个作为入口），与 Jev 并行起跑，结果用于一致性校验、拒识兜底和非入口域回流
设计原则：精准优先，错了往慢思考兜。Agent 直达和 NLU 直达都是“一次执行、不经规划”，判错了用户直接听到错误结果；慢思考能复用全部 NLU 技能和 Agent，判进去最多是慢一点。所以两条直达路径都设准入门槛，拿不准就进慢思考，而不是反过来。

02四个去向和准入条件

NLU 直达

  • 说清楚的指令（含无标点多意图、同功能多参数），落在 NLU3.0 的 19 个入口域（第 06 节）
  • NLU3.0 自己也接住：domain 不是 other，intent 不为空、必填槽位齐全（NLU3.0 不输出置信度，只看结构）
  • Jev 与 NLU 的 domain 一致（或在可接受的近邻对里）

例：关闭前挡风玻璃加热、导航到天安门、放一首稻香、给张三打电话

Agent 直达

  • 单轮、单个意图，交给 一个 Agent 一次就能答完
  • agent_label 不是 none，且 route 和 label 两个置信都过门槛
  • 不依赖未解析的上文指代，不和别的任务串联

例：最新的科技新闻（新闻）、今天星期几（联网搜索）、胎压报警灯亮了是怎么回事（用车专家）、每周一早上八点提醒我交周报（任务大师）

慢思考

  • 片段之间有依赖、跨任务约束、需要规划
  • 一句话里多个任务分属不同能力且有依赖（导航过去再在附近找餐馆、打电话说地点再导航过去）
  • 兜底：NLU3.0 落到 other 或解析不完整、Jev 与 NLU 的 domain 对不上、两条直达路径置信都不够

例：打开空调，导航到大裤衩，在附近找个人均 100 以下的川菜馆；打个电话给小李说聚餐地点定在渔人码头然后导航过去

闲聊

  • 没有任务目标的开放对话：讲故事、陪聊、情绪表达、写诗写文案（知识问答不归闲聊，见第 06 节）
  • 上一轮是闲聊且本轮是追问，代码直接跟随
  • 音频直通 S2S 端到端语音，不经 NLU、不改写

例：给甜甜讲首故事、（闲聊中）那后来呢

慢思考是“剩余类”：不是闲聊，又进不了两条直达路径的，都进慢思考。这样定义保证每句话都有去处，且直达路径的精确率可以单独调高。

03分流总流程

0
会话检查（代码） ① 慢思考有进行中的任务（大脑返回 continue）→ 交慢思考；② 上一轮 Agent 直达且该 Agent 返回 continue（还在等用户确认、补信息）→ 交回同一个 Agent；③ 上一轮是闲聊且本轮是追问 → 跟随闲聊。上一轮 Agent 已结束、本轮依赖上文的，在第 5 步按 R1 处理。
占用会话 → 慢思考Agent 会话 → 同一 Agent闲聊追问 → 闲聊
1
干预表（云端配置，精确匹配 + 规则 + 敏感词） 命中直接定去向（含 domain 或 agent_label），跳过 Jev。用于线上止血、高频确定句；敏感词命中直接交安全拒答。
命中 → 按表分发 / 安全拒答
2
预切分（代码）+ 并行起跑 只按强分隔切：标点和“然后、再、之后、顺便”等连接词，最多 4 段，只给 Jev 判片段角色用。同时发出 Jev 请求和 NLU3.0 请求（整句），两者互不等待。NLU3.0 能识别无标点的多意图（打开座椅通风座椅按摩）和同功能多参数，所以 NLU 始终拿整句，不按切分结果拆开调用。
3
Jev 一次请求 并行回答 is_unsafe / route / domain / agent_label / needs_context / has_nickname / segment_role[i]（多段时才问）。见第 04 节。
4
Query 整理（按需） has_nickname 为真：交 DeepSeek 把俗称还原成标准名称；needs_context 为真且不跟随上一轮（闲聊或 Agent）时：先用上文候选拼回指代对象，拼不回交 DeepSeek 改写。改写后回 Jev 重判一次（重判不再改写，防止循环）。
5
分发策略（代码，规则按顺序匹配） 读 Jev 答案 + NLU3.0 结果，按第 05 节的规则得出去向。只读与去向相关的答案，其余丢弃但记日志。
NLU 直达Agent 直达慢思考闲聊安全拒答
6
快思考落域失败 → 慢思考（R7） 落域前失败（R3 门槛不过、R4 检查不过、other 改写重判后仍接不住）在第 5 步已直接落慢思考；落域后被拒——业务侧回传“不支持该 intent”或 Agent 判定“不归我”——由分发把这一句改落慢思考一次（带原落域结果和被拒原因），不再回分流，避免来回弹。业务内部的执行故障（服务超时等）由业务侧处理，不算落域失败。

04Jev 一次请求的问题

问题类型问什么代码怎么用
is_unsafeNoul是否在求助违法犯罪、暴力伤害、毒品、自残等有害内容≥ T_UNSAFE 直接交安全拒答，优先于所有去向
routeChoice · 4 选 1NLU 直达 / Agent 直达 / 慢思考 / 闲聊取最高概率项和置信（4 选项：conf = (p_max − 1/4) ÷ (3/4)）。也读第二名，用于“NLU 直达 vs 慢思考”拿不准时的兜底判断

agent_labelChoice · N + none该交给哪个可直达的 Agent（第 06 节清单）走 Agent 直达时读；NLU3.0 落到非入口域需要回流时，也读对应 Agent 的概率

route 的判据要点（写进 criteria v3）

选项判为它不判为它
NLU 直达一条或连着几条说清楚的指令，落在 19 个入口域：车控、按名或按风格点播和播放控制、电话微信、导航去说得出名字的地点和导航控制、车家互联、壁纸主题绘画、计算；同一功能带多个参数也算新闻（→ 新闻）；天气（→ 天气）；股票、航班火车、限行、日期等即时信息和通用知识问答（→ 联网搜索）；用车相关（→ 用车专家）；条件任务、提醒、长期规则（→ 任务大师）；按描述找歌找片（→ 音乐 / 影视）；找店找景点、行程（→ 出行导航）；只说感受（→ 自适应车控）；记住或调用个人信息（→ 记忆）；打开新闻应用这类应用开关仍是 NLU
Agent 直达单个意图，一个 Agent 一次答完：新闻；天气；与新闻无关的即时信息和知识问答；用车相关；条件任务、提醒和长期规则；记住或调用个人信息；按描述找歌找片；找店找景点和行程；只说感受的车控；一个明确的代办单需要串联别的能力；违法有害请求
慢思考多个任务分属不同能力且有依赖、跨任务约束；NLU3.0 接不住、又没有 Agent 能直达的请求几条互不依赖的普通指令（那是 NLU 直达）
闲聊没有任务目标：讲故事、陪聊、情绪表达、写诗写文案；饿、渴、困、累这类车控满足不了的诉求只说感受但隐含车控（“好热”→ 自适应车控）；有标准答案的知识问答（→ 联网搜索）

05分发策略（代码规则）

规则从上到下匹配，命中即停。阈值是初值，全部放配置中心，在 val 上标定（第 10 节）。

NLU_ENTRY = {19 个入口域}                       # 第 06 节
DOMAIN_TO_AGENT = {"weather_xf": "天气", "life_suggestion": "天气", "news": "新闻",
                   "stock|flight|train|traffic_restriction|datetime_info": "联网搜索",
                   "help|intelligent_car_info": "用车专家", "music_qa": "音乐", "video_qa": "影视",
                   "poi_recommend|view_poi_*|similar_poi|outgoing_eta|travel_plan": "出行导航",
                   "intelligent_car_scenario": "自适应车控", "reminder|task_setting": "任务大师",
                   "agent_task|app_agent": "代办点单",      # shadow 期间等同进慢思考
                   "chat": CHAT, "outside_qa": SLOW}       # chat 交闲聊；车外问答本期进慢思考

def dispatch(jev, nlu, sess, segs):
    # R0 安全
    if jev.is_unsafe >= T_UNSAFE:                       return SAFE_REFUSE()
    # R1 会话（第 03 节第 0 步已处理 continue 的情况，这里处理“上一轮已结束、本轮依赖上文”）
    if sess.last_route == "chat"  and jev.needs_context: return CHAT(reason="闲聊追问")
    if sess.last_route == "agent" and jev.needs_context \
       and jev.route.top != "nlu":                       return AGENT(sess.last_agent, reason="Agent 追问")
    # R2 多段（整句本身是同一个 Agent 的请求时先直达，如“先去 A 再去 B”）
    if len(segs) >= 2 and agent_ok(jev):              return AGENT(resolve(jev.agent_label.top))
    if len(segs) >= 2:
        roles = merge_fragments(jev.segment_role)        # 残片并入前一段，“同一任务”与相邻片段合并
        if len(roles) == 1:  return dispatch_single(jev, nlu, sess)   # 合并后只剩一组：按单句走 R3–R6
        inst  = [s for s, r in roles if r == "独立指令"]
        rest  = [s for s, r in roles if r != "独立指令"]   # 独立 Agent 类 + 有依赖
        if not rest:   return nlu_path(jev, nlu)         # 全是指令：整句交 NLU3.0（它自己拆多意图）
        if not inst:   return SLOW(reason="多段含 Agent 类或依赖", hint=jev.agent_label.top)
        return SPLIT(nlu=nlu_path(jev, NLU3(join(inst))), slow=rest)   # 本期不做多 Agent 并发
    # R3 Agent 直达（精准门槛）
    if jev.route.top == "agent":
        if agent_ok(jev):                                # route.conf ≥ T_AGENT_ROUTE 且 label ≠ none 且 label.conf ≥ T_AGENT_LABEL[label]
            return AGENT(resolve(jev.agent_label.top))   # 回退表：新闻 / 天气 off → 联网搜索；shadow → 慢思考
        return SLOW(reason="Agent 直达置信不足", hint=jev.agent_label.top)
    # R4 NLU 直达（需要 NLU3.0 也接住）
    if jev.route.top == "nlu" or (jev.route.top == "slow" and jev.route.second == "nlu"
                                  and jev.route.conf < T_SLOW_SURE):
        return nlu_path(jev, nlu)
    # R5 闲聊
    if jev.route.top == "chat" and jev.route.conf >= T_CHAT: return CHAT()
    # R6 剩余（R7 落域后被拒在业务侧回传后触发，见第 03 节第 6 步）
    return SLOW(reason="剩余类", hint=jev.agent_label.top)

def nlu_path(jev, nlu):
    # nlu.intents 可能有多个（多意图）；每个都要过下面的检查
    if jev.domain.top == "非入口":                      # 信号 2
        return SLOW(reason="Jev 认为不在入口域", hint=jev.agent_label.top)
    for it in nlu.intents:
        if it.domain not in NLU_ENTRY:                   # 落到非入口域：回流对应 Agent
            agent = DOMAIN_TO_AGENT.get(it.domain)
            if len(nlu.intents) == 1 and agent and is_on(agent) \
               and jev.agent_label.prob[agent] >= T_REFLOW:
                return AGENT(resolve(agent), reason="NLU 落非入口域，回流")
            return SLOW(reason="NLU 含非入口域", hint=agent)
        if it.domain == "other" and not rewritten:         # 信号 3：先改写重判一次
            return REWRITE_AND_REJUDGE()
        if it.domain == "other" or not it.intent or missing_required_slots(it):   # 信号 3、4
            return SLOW(reason="NLU3.0 接不住")
        if not (consistent(jev.domain.top, it.domain) or jev.domain.prob[it.domain] >= T_DOMAIN_AGREE):
            return SLOW(reason="domain 不一致")
    return NLU(nlu.intents)

几处取舍

  • NLU 入口白名单：NLU3.0 仍会对“明天苏州天气”输出 weather_xf。只有 19 个入口域可以直达执行；落到其他域时按 DOMAIN_TO_AGENT 回流给对应 Agent，前提是 Jev 也给了该 Agent 一定概率（≥ T_REFLOW），否则带提示进慢思考。这样即使 Jev 的 route 判错成 NLU，也不会绕过已定的 Agent 归属。
  • route 置信低时，v5 原稿写“NLU 落域兜底”。本设计改成：Jev 在 NLU 和慢思考之间拿不准时，看 NLU3.0 自己接不接得住——接得住且 domain 一致就直达执行，接不住就慢思考。
  • domain 一致性：consistent() 认同一域，也认入口域之间的近邻对（如 intelligent_car_control↔global_control、music↔audio_book），近邻时以 NLU 的为准。NLU3.0 不输出置信度，用 Jev 的 domain 分布代替：Jev 给 NLU 选的域的概率 ≥ T_DOMAIN_AGREE 就按 NLU 执行。不一致率作为监控指标。
  • 多指令整句交 NLU3.0：NLU3.0 能识别无标点多意图和同功能多参数，所以全是指令时不按预切分拆开调用，避免把“打开空调并把温度调到 26 度风量三档”拆错。只有混了 Agent 类或有依赖片段时，才把独立指令片段拼起来另调一次 NLU3.0。
  • 同一 Agent 的多段句：“先去长沙橘子洲头，再去岳麓书院”会被“再”切成两段，但整句是出行导航一个 Agent 能完成的，R2 先按整句判 Agent 直达；只有跨能力的多段才拆分。
  • Agent 追问：上一轮是 Agent 直达、本轮依赖上文（needs_context）（那喝水呢、时间改成三天两夜吧、钢琴博物馆不去了），直接交回同一 Agent，由 Agent 用自己的上下文理解，不做改写。若本轮其实是一条新指令（route 判为 NLU），不跟随。
  • Agent 直达置信不足时带 hint 进慢思考：大脑拿到“前置分流提示：联网搜索”，大多数情况一次就会调同一个 Agent，只多一次规划的耗时。

06Agent 精准直达

归属规则（2026-10-28 已定）：和新闻相关的走新闻 Agent；和新闻无关的即时信息查询走联网搜索；知识问答和用车相关的走用车专家，和用车无关的走联网搜索；条件任务归任务大师。新闻 Agent 未接入或关闭时，新闻类请求由联网搜索处理。用车专家是 Agent，用车相关的问题（包括状态询问）都由它处理，不走 NLU。

只有“一句话、一个 Agent、一次答完”的才进清单。每个 label 对应 Agent Hub 注册表里的一个 Agent 或 Tool，各自有独立的置信门槛，可以单独 on / shadow / off。

要。NLU3.0 不输出置信度，Jev 的 domain 分布是判断“NLU 落得对不对”的唯一依据，同时用来监控 NLU 漂移。

Q6c · 音乐、影视、出行导航、车控模糊意图；有情知音；记忆调用 已定
前四类都走 Agent 直达；有情知音按闲聊处理；记忆调用按业务归记忆 Agent。
Q6b · 天气、股票、航班火车、限行 已定
天气归新增的天气 Agent（未接入时回退联网搜索）；股票、航班火车、限行归联网搜索；NLU 对应域只做兜底。注意：这些查询原来有 NLU 的结构化卡片，改走联网搜索后要确认端侧展示怎么处理。
Q7 · NLU3.0 不输出置信度，“接不住”怎么判？
只用结构信号：domain = other、intent 为空、必填槽位缺失；对错由 Jev 的 domain 分布校验（第 07 节信号 3–5）。需要 NLU 团队确认两件事：接不住时是否固定落 other；能否提供各 intent 的必填槽位表。
让 NLU3.0 增加一个显式的拒识输出（如 domain = none），比靠 other 判断更干净。
Q8 · 新测试集的改标规则谁来定？
保留业务标签，用映射表换算去向，见《Jev 分流测试方案》第 03、04 节。
Q9 · 对照测试方案审阅后的架构补充 已定（10-29）
① NLU 入口白名单 + 非入口域回流 Agent（R4、信号 6）；② Agent 会话跟随：Agent 返回 continue 时交回同一 Agent，Agent 已结束而本轮依赖上文的也交回（第 0 步、R1）；③ 安全拦截：Jev 加 is_unsafe，干预表加敏感词（R0）；④ 片段角色扩为五类（10-29 冒烟后加“同一任务”），全是指令时整句交 NLU3.0（它能识别无标点多意图和同功能多参数）；⑤ domain 题改为 19 个入口域 + 非入口。
