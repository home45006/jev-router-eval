Jev 前置分流判断流程

Jev 一次请求给每句话打一个标签，共 28 个：NLU 侧输出 16 个 domain，Agent 侧输出 12 个 label。标签决定这句话去哪个分支。闲聊追问、改写拆分、置信度兜底由代码按固定顺序处理。

判断流程

Jev 的三个问题

三个问题放在同一次请求里，共用同一份输入：query、previous_turn（上一轮的内容和标签）、now_playing（当前播放的媒体）。它们互相看不到对方的答案，组合逻辑写在代码里。

问题类型问什么代码怎么用
label Choice
28 选 1		 这句话应当归入哪个标签。每个选项写明包含什么、不包含什么，并附几条例句 取概率最高的标签。同一分支下各标签的概率相加，得到分支概率，用于置信度不达标时的兜底
is_followup Noul
是的概率		 这句话是不是对上一轮的追问或延续。只在有上一轮时才问 上一轮是闲聊且为是：输出闲聊。上一轮不是闲聊且为是：先改写再判标签
is_multi Noul
是的概率		 这句话里是不是有两条或更多可以分别执行的指令 用来校验。label 判成单条指令但 is_multi 很高时，按置信度不达标处理

代码里的决策顺序

  1. 查精确匹配表。命中的标准说法直接输出 domain，不经过 Jev。“语义”sheet 的 4,481 条唯一说法可以直接入表。
  2. 判断闲聊追问。上一轮标签是闲聊，且 is_followup 达到阈值，输出闲聊，不看 label 选了什么。
  3. 判断改写和拆分。label 是中枢简单任务，就拆成多条；是非闲聊会话里的追问，就补全成能独立理解的一句。高频追问先用槽位继承，解不了再调大模型。得到的每条指令再过一次 Jev。
  4. 检查置信度。达标的按标签走。不达标的看分支概率：分支明确就按分支走，NLU 侧交给现有落域去判 domain；分支也不明确，走慢思考。
  5. 分发。16 个 domain 去 NLU 直达，9 个 agent label 去对应 Agent，中枢复杂多任务去慢思考编排，闲聊去端到端语音接口。
  6. 兜底。NLU 直达落域失败或置信度低，升级到慢思考。

已确认的规则

规则怎么落地
语义 sheet 输出预期 domain，一律首字母小写原表 23 种写法合并成 16 个 domain。“类别”列不再是标签
“全局”类别表示任何场景下都可以说它是可说范围，不影响标签。评测集里保留为一个标记
闲聊会话里的追问一律跟随上一轮代码实现，见决策顺序第 2 步
带时间或触发条件的请求分三类：提醒、一次性任务、周期性任务见下表

带时间或触发条件的请求

标签判据谁来理解例句
scheduleReminder到时间提醒用户去做某事，系统不替用户执行动作传统 NLU，速度快下午3点提醒我开会
条件任务一次性任务：到时间或快到目的地时，车机直接执行，只执行这一次大模型 Agent晚上八点打开氛围灯
任务大师周期性任务：每天每周重复，或每当某个事件、状态出现就触发大模型 Agent每天八点主动播放电影；当我上车时自动播报公主请上车

测试集里任务大师共 551 条，只有 12 条带“每天、每周”，535 条是“每当某事发生就执行”的长期规则，这里都按周期性任务处理。条件任务 520 条里没有一条带周期词，和定义一致。

现状和风险

官方文档写明 Jev 主要用英文训练，中日韩文字能处理但准确率不如英文，并建议先用自己的数据测试。Jev 能不能用在这里，取决于评测结果。

已经有的

  • 评测集 13,662 条，按句式模板分组后切成 dev 2,814、val 2,728、test 8,120。
  • 28 个选项的判据初稿，例句只取自 dev。
  • 评测脚本，输出准确率、混淆和阈值分析。流程已用模拟数据跑通。
  • 参照线：只看字面的 n-gram 分类器在同一份数据上是 96.5%。Jev 至少要超过它。

还没有的

  • Jev 的实测结果。需要密钥。
  • 闲聊中途说一条新指令的样本。现有 574 条多轮样本全是闲聊追问，测不到能否跳出闲聊。
  • 非闲聊追问的样本，例如调完空调后说“再高一点”。改写这条路径没有评测数据。
  • 样本很少的 domain：memoryRecord 2 条、unicast 7 条、phone 15 条、scheduleReminder 16 条、navi 19 条。

接入现状：快思考模型未接入，NLU 直达先用现有方式落域；慢思考编排未接入，先只出标签。

待确认

  • “条件任务”下有 128 行只是提醒、没有车机动作，例如“五号上午九点提醒我打卡”。按定义应归 scheduleReminder，但其中约六成说法很口语，传统 NLU 未必接得住。需要决定：一律归 scheduleReminder，还是只有规范说法归它、口语化的留在条件任务。另有 85 行需要逐条判断。
  • 任务大师里有 4 行疑似一次性任务，例如“15分钟后自动关闭视频”“等会下车提醒我拿包”，需要确认是否改成条件任务。
  • 首轮闲聊和各 agent 的界线。原标注不一致：“有没有惊悚电影推荐”标闲聊，“推荐户外露营的电影”标影视agent。判据暂按“属于某个 agent 领域的优先归该 agent”写。
  • 16 个 domain 的判据是从测试集归纳的，需要熟悉 NLU 的同事核对。
  • 各阈值：label 的置信度门限，is_followup 和 is_multi 的概率阈值。在 val 上标定。
  • 拆分后的多条指令是串行还是并行执行，其中一条失败时怎么播报。
