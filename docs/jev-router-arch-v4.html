Jev 前置分流架构

快思考模型已经覆盖语音 NLU 的全部理解，Jev 不再判断 NLU 的 domain。Jev 先只回答一个问题：这句话该不该交给快思考？交给快思考的到此为止；剩下的再由第二级 Jev 判断去哪个 Agent。两级判据各管一件事，可以分开开发和评测。

第 4 版 · 2026-10-11 · 取代第 3 版的“28 个标签一次判完”。成本和 token 数字中标“估”的是估算，其余为实测

代码里的决策顺序

  1. 查精确匹配表。命中就返回缓存的快思考结果，不调 Jev。表里只放快思考在线上解析稳定的高频说法，随快思考模型版本一起更新。
  2. 调第一级 Jev。一次请求问 is_fast，有上一轮时同时问 is_followup。
  3. 判断闲聊追问。上一轮是闲聊，且 is_followup 达到阈值，输出闲聊，不看 is_fast。
  4. 判断是否交给快思考。is_fast 达到阈值就交给快思考。是非闲聊会话里的追问（如调完空调后说“再高一点”），先带上一轮的 domain 和槽位做继承，继承不了再调大模型补全。
  5. 快思考兜底。快思考输出拒识或置信度低于门限，升级到第二级 Jev，这时第二级不带“退回快思考”选项，避免来回绕。
  6. 调第二级 Jev。12 个 agent label 加“退回快思考”选一个。
  7. 分发。置信度达标按 label 走：9 个 agent label 去对应 Agent，中枢简单任务拆分后每条交给快思考，中枢复杂多任务去慢思考编排，闲聊去端到端语音，退回快思考的交给快思考。置信度不达标走慢思考编排。

第一级判据怎么写

第一级的判据只回答“这句话是不是快思考能直接理解的一条指令或查询”。它不需要区分 16 个 domain，只需要写清快思考覆盖的范围，以及和 agent 之间的分界。覆盖范围以快思考团队维护的能力清单为准，判据从清单生成，快思考扩大覆盖时同步更新。

交给快思考

一句话里只有一条说清楚了的直接指令或简单查询。

  • 车控、车窗座椅空调、HUD、驾驶模式、能量充电
  • 打开关闭应用和页面，各类音量、亮度、网络、语音设置
  • 按歌名、歌手、片名、节目名点播；播放控制和收藏
  • 导航去说得出名字的地点；导航过程和地图控制；到家、公司、当前目的地的距离和路况
  • 智驾和泊车指令；场景模式；电话
  • 胎压、空调温度、保养、存储空间这几项数值查询
  • 到时间提醒用户做某事；查询、删除日程

不交给快思考

需要理解、检索、规划，或者带触发条件、有多条指令。

  • 只说感受没说指令（“热得浑身不自在”）
  • 问本车功能是什么、怎么用、为什么坏、是否正常
  • 按氛围、歌词、剧情找歌找片；让系统推荐
  • 靠描述找地点、多地点行程、去某个具体地名要多久
  • 新闻资讯；记住个人信息
  • 一次性定时动作（条件任务）、长期规则（任务大师）
  • 一句话里有两条以上指令；开放问答和闲聊

第 3 版判据里“domain 和 agent label 之间”的那张边界表，现在就是第一级判据的全部内容；“domain 之间”的边界（如中控亮度归 carControl 还是 systemControl）交还给快思考，Jev 不再管。

两种判错，代价不同

错误例子后果能不能兜回来
该走 Agent，交给了快思考“空调是不是坏了” 被当成空调指令快思考可能硬落一个 domain，执行错误动作只有快思考拒识或低置信时才能升级。依赖快思考的拒识能力
该走快思考，送到了第二级“打开空调页面”多一次 Jev 调用，延迟增加第二级选“退回快思考”即可回到正路

因此 is_fast 的阈值偏向保守：拿不准的句子送第二级。在 val 上标定时，先把“该走 Agent 却交给快思考”的比例压到目标以下，再看送到第二级的比例是否可以接受。

调用量和成本

设线上不经过精确匹配表的句子里，比例为 p 的句子交给快思考。第一级每句都调，第二级只有其余的句子调：

每句平均输入 token ＝ T₁ ＋ (1 − p) × T₂　　每句平均 Jev 调用次数 ＝ 1 ＋ (1 − p)

T₁：第一级请求，两个 Noul，判据约为快思考范围加边界清单，估 2,500 token。T₂：第二级请求，12 个 label，按 v0.5 判据中 agent 选项所占篇幅折算，估 4,000 token。第 3 版的实测值为每句一次请求、平均 7,882 token。

省下来的是 token，不是调用次数。第一级每句都要调一次，不走快思考的句子还要调第二次，所以调用次数比第 3 版略多。如果 Jev 按 token 计费，这个架构省一半以上；如果按次数计费，要靠精确匹配表的命中率来省。

延迟参考：评测中 409 条请求在 8 路并发下约 6 秒跑完，单次约 0.1 秒。这是 GitHub 美国机房测得的，车端链路需要另测。走第二级的句子要串行调两次 Jev。

后续可选：快思考先跑

如果快思考的拒识足够可靠，可以把第一级去掉：所有句子先交给快思考，快思考拒识的才调 Jev。Jev 调用次数降到 (1 − p)，p = 80% 时每句平均约 860 token估。

好处

  • 交给快思考的句子完全不调 Jev
  • 不需要维护第一级判据

前提和代价

  • 快思考必须对“空调是不是坏了”这类句子拒识，而不是硬落 domain
  • 不走快思考的句子多一段快思考的延迟
  • 快思考要知道自己不管什么，又把边界放回了快思考模型里

这件事可以先测：测试集里有 9,000 多条 agent 侧的句子，全部送给快思考，看它的拒识率。拒识率足够高，再考虑切换。

模块之间的约定

约定内容谁维护
快思考能力清单快思考覆盖的 domain 和说法范围，以及明确不管的类型。第一级判据从它生成快思考团队
快思考输出domain、意图、槽位、置信度，以及拒识标记。拒识和置信度是兜底升级的唯一依据，必须有快思考团队
第一级判据is_fast 和 is_followup 两个问题的说明和例句分流团队
第二级判据12 个 agent label 和“退回快思考”的说明、不包含什么、例句分流团队，和各 Agent 负责人对齐
阈值is_fast、is_followup、第二级置信度、快思考置信度在 val 上标定，随判据版本发布

快思考新增 domain 时，只要不改变它和 agent 的边界，第一级判据和第二级判据都不用动。新增一个 Agent 时，只改第二级判据，以及在第一级“不交给快思考”里补一行。

评测怎么做

现有的 13,662 条评测集不用重标。“语义”sheet 的句子就是第一级的“交给快思考”，“大模型agent”sheet 的句子是“不交给快思考”，第二级的标准答案就是原来的 label。

待确认

  • 快思考能否直接处理一句话里的多条指令。能的话，多条直接指令可以在第一级就交给快思考，省掉第二级和拆分；不能的话按本文设计，走中枢简单任务拆分。
  • 快思考有没有拒识输出和可用的置信度。兜底升级完全依赖它。
  • 快思考是否接收上一轮的 domain 和槽位。接收的话，非闲聊追问不需要大模型补全。
  • 第二级要不要“退回快思考”选项。本文默认要；去掉的话第二级判据更纯，但第一级送错的句子回不到快思考。
  • “条件任务”下 128 行纯提醒。提醒归快思考，条件任务归第二级，这件事现在决定句子走哪一级，需要先定口径。
  • 闲聊和影视 agent 的界线。原标注不一致，只影响第二级。
  • 线上交给快思考的比例 p 和精确匹配表的命中率。用线上日志统计后，替换上面成本表里的估算值。
