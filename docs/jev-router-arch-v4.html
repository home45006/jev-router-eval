Jev 前置分流架构

快思考模型已经覆盖语音 NLU 的全部理解，Jev 不再判断 NLU 的 domain。Jev 先回答：这句话该不该交给快思考？要不要先把模糊指代改写成标准说法？交给快思考的到此为止；剩下的再由第二级 Jev 判断去哪个 Agent。两级判据各管一件事，可以分开开发和评测。

第 13 版 · 2026-10-11 · 闲聊也作为 Agent 交给 Agent 大脑，由大脑判断用户是否在闲聊；第一级去掉 is_followup，第二级 5 选 1 加“退回快思考”。

两层体验

测试集里的 query 保证基础交互体验，智能体现在 Agent 大脑上。前置分流的任务是把基础体验的句子准确、快速、低成本地交给快思考或直达的 Agent；其余的交给大脑，由它自主编排调度各项能力。

两种分错的代价不同：基础体验的句子误入大脑，只是慢一点、贵一点，结果通常仍然正确；需要智能的句子被留在快车道，会被当成字面指令执行或直接失败。所以分流拿不准时，倾向交给大脑。

代码里的决策顺序

  1. 检查会话占用。有进行中的会话，就把这句直接交给占用会话的 Agent，不调 Jev。Agent 返回“继续”或“结束”则本轮到此为止；返回“不归我”则会话挂起，这句从下一步开始走正常流程，处理完后会话恢复。没有会话的直接进入下一步。
  2. 调第一级 Jev。一次请求并行问 is_fast 和 needs_rewrite。
  3. 判断是否交给快思考。is_fast 达到阈值：needs_rewrite 也达到阈值的，先调大模型把模糊指代改写成标准名称，再交给快思考；否则直接交给快思考，连同上一轮一起，上下文指代（“再高一点”“换成第二个”）由快思考自己消解。
  4. 快思考兜底。快思考拒识或置信度低于门限，升级到第二级 Jev，这时第二级不带“退回快思考”选项，避免来回绕。改写后仍被拒识的，同样升级。
  5. 调第二级 Jev。is_fast 没达到阈值，或从快思考升级来的句子，在任务大师、条件任务、联网搜索 Agent、用车手册 Agent、Agent 大脑和“退回快思考”里选一个。
  6. 分发。置信度达标按 label 走：4 个独立 Agent 直接调用，退回快思考的交给快思考，其余（包括闲聊）交给 Agent 大脑。置信度不达标也交给 Agent 大脑，由它决定怎么完成。走 Agent 的句子不需要先改写，Agent 自己是大模型，能理解模糊指代。

Agent 大脑

第二级判为中枢复杂多任务的句子交给 Agent 大脑。它先理解用户要完成的整件事，再自主决定调用哪些能力、按什么顺序调用，一步一步把事情做完。座舱的智能主要体现在这里。

和前面几条路径的关系：

  • 直达是捷径，大脑是上限。单个 Agent 就能办完的事，第二级直接派给它，省掉大脑的规划，响应更快、更省。需要多个能力配合的，交给大脑。
  • 拿不准的交给大脑。第二级置信度不足时不再猜标签，交给大脑，由它决定调谁、调几个。这样分流判错的代价最小。
  • 大脑持有会话。编排过程中用户的后续发言先到大脑，大脑再转给正在对话的子 Agent（如美团 Agent）。子 Agent 说“不归我”时，先由大脑判断这句是不是任务里的另一步（如“顺便导航过去”）；大脑也认为不属于当前任务，才交回 Jev 第一级。

会话占用

点外卖、选目的地这类任务通常要和用户来回好几轮才能完成，比如用美团点外卖：选店、选菜、确认地址、下单。进入这类任务后，后续轮次如果每轮都重新过 Jev，既费调用，又容易判错：“要中辣的”“第二个”单看一句话，Jev 判断不了是在点外卖。所以这类任务开始后，由对应的 Agent 占用会话，后续轮次直接交给它。

Agent 每轮返回三种状态之一

状态例子（点外卖过程中）系统怎么做

由 Agent 判断，而不是每轮再问一次 Jev，是因为 Agent 掌握完整的任务上下文（选了哪家店、购物车里有什么），对“第二个”“换一家”的理解比只看上一轮的 Jev 更准。这和快思考的拒识是同一个思路：由执行方判断自己能不能接这句话，接不了的交回分流。

系统兜底

不能全靠 Agent 自觉放手，代码层面还有四条：

  • 超时：一段时间没有交互就释放会话，时长按场景标定。
  • 轮数上限：防止卡在同一个 Agent 里出不来。
  • 退出词：“退出”“取消”“回到主页”直接释放会话，不问 Agent。
  • 重新唤醒：用户重新说唤醒词时，会话保留，但这一句先过 Jev 第一级，再决定是否交回 Agent。

第一级判据怎么写

第一级的判据只回答“这句话是不是快思考能直接理解的一条指令或查询”。它不需要区分 16 个 domain，只需要写清快思考覆盖的范围，以及和 agent 之间的分界。覆盖范围以快思考团队维护的能力清单为准，判据从清单生成，快思考扩大覆盖时同步更新。

交给快思考

一句话里只有一条说清楚了的直接指令或简单查询。

  • 一句话连说几条直接指令（原来的中枢简单任务），快思考能整句处理
  • 车控、车窗座椅空调、HUD、驾驶模式、能量充电
  • 打开关闭应用和页面，各类音量、亮度、网络、语音设置
  • 按歌名、歌手、片名、节目名点播；播放控制和收藏
  • 导航去说得出名字的地点；导航过程和地图控制；到家、公司、当前目的地的距离和路况
  • 智驾和泊车指令；场景模式；电话
  • 胎压、空调温度、保养、存储空间这几项数值查询
  • 到时间提醒用户做某事；查询、删除日程

不交给快思考

需要理解、检索、规划，或者带触发条件、有多条指令。

  • 只说感受没说指令（“热得浑身不自在”）
  • 问本车功能是什么、怎么用、为什么坏、是否正常
  • 按氛围、歌词、剧情找歌找片；让系统推荐
  • 靠描述找地点、多地点行程、去某个具体地名要多久
  • 新闻资讯；记住个人信息
  • 一次性定时动作（条件任务）、长期规则（任务大师）
  • 多条指令里有需要推断、查询或互相依赖的步骤；开放问答和闲聊

第 3 版判据里“domain 和 agent label 之间”的那张边界表，现在就是 is_fast 判据的主体；“domain 之间”的边界（如中控亮度归 carControl 还是 systemControl）交还给快思考，Jev 不再管。is_fast 只看指令类型，不看对象说得是否标准：“导航到大裤衩”的 is_fast 应为是，它的问题交给 needs_rewrite。

调用量和成本

设线上的句子里，比例为 p 的句子交给快思考，其中比例为 r 的带模糊指代需要改写。第一级每句都调，第二级只有其余的句子调：

每句平均 Jev 输入 token ＝ T₁ ＋ (1 − p) × T₂　　每句平均 Jev 调用次数 ＝ 1 ＋ (1 − p)　　每句平均改写调用 ＝ p × r

T₁：第一级请求，三个 Noul，判据约为快思考范围、边界清单和模糊指代正反例，估 2,800 token。T₂：第二级请求，6 个选项，估 2,500 token。第 3 版的实测值为每句一次请求、平均 7,882 token。改写调用的是通用大模型，不计入 Jev。

后续可选：快思考先跑

快思考已经有拒识能力，所以可以考虑把第一级去掉：所有句子先交给快思考，快思考拒识的才调 Jev。Jev 调用次数降到 (1 − p)，p = 80% 时每句平均约 860 token估。

好处

  • 交给快思考的句子完全不调 Jev
  • 不需要维护 is_fast 的判据

前提和代价

  • 快思考要对“空调是不是坏了”这类句子拒识，而不是硬落 domain。拒识能力有了，召回率还要测
  • 模糊指代仍然需要单独检测。“导航到大裤衩”的句式快思考能理解，它不会拒识，只会把“大裤衩”原样当成目的地。所以即使快思考先跑，needs_rewrite 这一问也省不掉
  • 不走快思考的句子多一段快思考的延迟

可以先测：测试集里有 9,000 多条 agent 侧的句子，全部送给快思考，看拒识率；再从线上日志里挑一批模糊指代的句子，看快思考是否会硬解。两项都达标，再考虑把第一级缩成只问 needs_rewrite，或者把这一问并进改写前的轻量检测。

快思考能力清单快思考覆盖的 domain 和说法范围，以及明确不管的类型。第一级判据从它生成快思考团队
快思考输入输出输入 query 和上一轮（query、domain、槽位）；输出 domain、意图、槽位、置信度、拒识标记。拒识和置信度是兜底升级的依据快思考团队
改写约定只把模糊指代换成标准名称，其余字词不动；还原不了就原样返回并标记失败，失败的句子直接升级到第二级分流团队
会话协议Agent 声明是否支持多轮；每轮返回继续、挂起、结束之一；挂起恢复后由 Agent 负责提示用户各 Agent 负责人，分流团队定协议
第一级判据is_fast、needs_rewrite 两个问题的说明和例句分流团队
第二级判据4 个独立 Agent、Agent 大脑和“退回快思考”的说明、不包含什么、例句分流团队，和各 Agent 负责人对齐
阈值is_fast、needs_rewrite、第二级置信度、快思考置信度在 val 上标定，随判据版本发布

快思考新增 domain 时，只要不改变它和 agent 的边界，第一级判据和第二级判据都不用动。新增一个 Agent 时，只改第二级判据，以及在第一级“不交给快思考”里补一行。

评测怎么做

现有的 13,662 条评测集不用重标。“语义”sheet 的句子就是第一级的“交给快思考”，“大模型agent”sheet 的句子是“不交给快思考”，第二级的标准答案就是原来的 label。

评测看什么现有参考
第一级该走 Agent 却交给快思考的比例；该走快思考却送到第二级的比例；按阈值画曲线v0.5 判据在 409 条 dev 上的 28 选 1 结果里，跨快思考和 Agent 边界的错误有 4 条，约 1%。这是从 28 选 1 折算的，第一级要单独测
第二级只用 agent 侧样本，5 个选项的准确率和混淆，以及落到 Agent 大脑的比例原来 12 个 label 里最难分的几对（闲聊和影视、音乐和多媒体、复杂导航和导航）现在大多都归大脑，预计准确率会明显上升
快思考拒识把 agent 侧样本送给快思考，统计拒识率和低置信率快思考已有拒识能力，召回率还没有在这批数据上测过
模糊指代needs_rewrite 的准确率；改写后快思考的理解正确率现有评测集里基本没有这类样本，要从线上日志补：地图搜索无结果、快思考槽位里出现俗称的句子
Agent 大脑任务完成率、调用了哪些能力、轮数和耗时测试集里中枢复杂多任务只有 186 条，而且只有单句。需要另建多轮场景集，覆盖跨能力的任务
会话放手多轮任务中途插入一句无关指令，Agent 是否正确返回“不归我”；正常的后续轮次是否被误放手现有 574 条多轮样本全是闲聊追问，没有复杂任务的多轮对话，需要补
端到端第一级、快思考、第二级串起来后，每句最终去向是否正确需要快思考的输出接口

待确认

  • 快思考上下文消解的范围。本文假设“再高一点”“换成第二个”“那到公司呢”这类都能处理，不在范围内的类型需要列出来，归到改写。
  • 改写的延迟上限。改写用 DeepSeek V4 Flash，它在快思考链路上串行，直接影响这部分句子的响应时间，需要实测。
  • 模糊指代的样本。需要从线上日志收集一批，才能写 needs_rewrite 的判据并标定阈值。
  • 第二级要不要“退回快思考”选项。本文默认要；去掉的话第二级判据更纯，但第一级送错的句子回不到快思考。
  • “条件任务”下 128 行纯提醒。提醒归快思考，条件任务归第二级，这件事现在决定句子走哪一级，需要先定口径。
  • 会话占用的超时时长、轮数上限和退出词清单。重新唤醒时会话保留还是释放，本文暂按保留写。
  • 各能力给大脑的接口约定。快思考、导航、空调、多媒体、美团、用车 Agent 和联网搜索各自的说明、输入输出和失败返回。
  • 联网搜索 Agent 接入前怎么落地。现在只出标签；上线前判为联网搜索的句子暂时交给 Agent 大脑兜底。
  • Agent 大脑和联网搜索 Agent 的界线。查股价、天气、限行这类原来标为闲聊的实时问题，交给大脑（大脑可调用搜索）还是直接给联网搜索 Agent。
  • Agent 大脑的延迟预算。多 Agent 编排比直达慢得多，需要定首句响应的上限，以及中间过程怎么播报。
  • 挂起后恢复时怎么提示用户。需要和 Agent 大脑、美团 Agent、导航 Agent 的负责人对齐。
  • 线上交给快思考的比例 p、模糊指代比例 r。用线上日志统计后，替换上面成本表里的估算值。
