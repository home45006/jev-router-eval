Jev 前置分流架构

快思考模型已经覆盖语音 NLU 的全部理解，Jev 不再判断 NLU 的 domain。Jev 先回答：这句话该不该交给快思考？要不要先把模糊指代改写成标准说法？交给快思考的到此为止；剩下的再由第二级 Jev 判断去哪个 Agent。两级判据各管一件事，可以分开开发和评测。

第 6 版 · 2026-10-11 · 精确匹配表改为自定义规则引擎，用来快速修复分流错误。快思考有拒识，能消解上下文指代，不能还原模糊指代。成本和 token 数字中标“估”的是估算，其余为实测

判断流程

代码规则 Jev 判断 快思考模型 Agent 慢思考 / 大模型 闲聊 兜底升级

大多数车控、媒体、导航指令只经过第一级 Jev 就交给快思考，包括“再高一点”这类上下文追问。只有带模糊指代的句子多调一次大模型改写，只有不归快思考的句子才走第二级。命中规则的句子连第一级都不经过：指定快思考的直接交给快思考，指定 agent label 或闲聊的沿左侧连线直接分发。

每一级做什么

环节谁来做输入输出只负责
规则引擎代码，配置热更新归一化后的 query、上一轮、播放状态去向：快思考，或某个 label已知分错的句式，在判据或模型修好之前强制落到正确去向
Jev 第一级Jev，三个 Noulquery、上一轮、播放状态is_fast、needs_rewrite、is_followup 三个概率快思考和非快思考的边界；有没有模糊指代；是否追问
大模型改写通用大模型query、上一轮把模糊指代换成标准名称后的一句话只处理要交给快思考、又带模糊指代的句子
快思考模型千问 8B 微调query（或改写后的句子）、上一轮domain、意图、槽位、置信度、拒识标记语音 NLU 的全部理解，包括 domain 之间的边界和上下文指代
Jev 第二级Jev，一个 Choice同第一级12 个 label 加“退回快思考”的概率12 个 agent label 之间的边界
分发代码第二级的概率去向置信度门限和兜底

代码里的决策顺序

  1. 过规则引擎。按优先级逐条匹配，第一条命中的规则决定去向：指定快思考的直接交给快思考（仍由快思考理解，拒识照样升级），指定 label 的直接分发，都不调 Jev。没有命中的继续往下。
  2. 调第一级 Jev。一次请求并行问 is_fast 和 needs_rewrite，有上一轮时同时问 is_followup。
  3. 判断闲聊追问。上一轮是闲聊，且 is_followup 达到阈值，输出闲聊，不看其他两个问题。
  4. 判断是否交给快思考。is_fast 达到阈值：needs_rewrite 也达到阈值的，先调大模型把模糊指代改写成标准名称，再交给快思考；否则直接交给快思考，连同上一轮一起，上下文指代（“再高一点”“换成第二个”）由快思考自己消解。
  5. 快思考兜底。快思考拒识或置信度低于门限，升级到第二级 Jev，这时第二级不带“退回快思考”选项，避免来回绕。改写后仍被拒识的，同样升级。
  6. 调第二级 Jev。is_fast 没达到阈值，或从快思考升级来的句子，12 个 agent label 加“退回快思考”选一个。
  7. 分发。置信度达标按 label 走：9 个 agent label 去对应 Agent，中枢简单任务拆分后每条交给快思考，中枢复杂多任务去慢思考编排，闲聊去端到端语音，退回快思考的交给快思考。置信度不达标走慢思考编排。走 Agent 的句子不需要先改写，Agent 自己是大模型，能理解模糊指代。

自定义规则引擎

Jev 判据和快思考模型的修正都要经过改判据或训练、评测、发版，周期以天或周计。线上发现一类句子分错了，规则引擎可以在判据修好之前，先用一条规则让这类句子落到正确的去向，配置下发后几分钟内生效。规则是补丁，不是第二套分类器。

一条规则包含什么

字段说明
匹配完全相等、正则、关键词组合三选一，在归一化后的 query 上匹配（去唤醒词、标点、空格，全角转半角，数字写法统一）
排除出现就不命中的词或正则。“打开空调”规则要排除“是不是坏了”“怎么用”这类问句
上下文条件默认只在没有上一轮、或上一轮不是闲聊时生效，避免截走闲聊追问。可以按上一轮 label、播放状态加条件
去向快思考，或 12 个 label 之一（含闲聊、中枢复杂多任务）。不能指定“改写”，模糊指代仍交给第一级判断
优先级数字越小越先匹配，第一条命中即停。窄规则排在宽规则前面
正例、反例每条规则至少附几条应当命中和不应命中的句子，没有就不能上线
来源和期限对应的 bug 单、负责人、复查日期
状态灰度（只记录命中、不改变去向）、全量、下线

防止规则误伤

  • 上线前跑回放。新规则提交后，自动把 13,662 条评测集和累积的回归集全部过一遍，报告它会截走多少句、其中多少句的标准答案和规则去向不一致。有不一致的必须逐条确认或收窄规则才能合入。
  • 先灰度。灰度状态只记录命中、不改变去向，看一两天线上命中的句子，确认没有误伤再转全量。
  • 命中可追溯。每次命中都记下规则编号，抽样复核；某条规则的命中量突然变化要报警。
  • 不绕过快思考的拒识。规则指定快思考的句子，快思考拒识或低置信时照常升级到第二级。

规则要退场

每条规则对应一个已知错误。修复同步进入下一版 Jev 判据或下一版快思考的训练数据；新版本在评测中确认这类句子已经判对，就下线这条规则。超过复查日期还在、或长期零命中的规则要复查。目标是规则数量保持在几十条的量级，而不是越积越多。

第一级判据怎么写

第一级的判据只回答“这句话是不是快思考能直接理解的一条指令或查询”。它不需要区分 16 个 domain，只需要写清快思考覆盖的范围，以及和 agent 之间的分界。覆盖范围以快思考团队维护的能力清单为准，判据从清单生成，快思考扩大覆盖时同步更新。

交给快思考

一句话里只有一条说清楚了的直接指令或简单查询。

  • 车控、车窗座椅空调、HUD、驾驶模式、能量充电
  • 打开关闭应用和页面，各类音量、亮度、网络、语音设置
  • 按歌名、歌手、片名、节目名点播；播放控制和收藏
  • 导航去说得出名字的地点；导航过程和地图控制；到家、公司、当前目的地的距离和路况
  • 智驾和泊车指令；场景模式；电话
  • 胎压、空调温度、保养、存储空间这几项数值查询
  • 到时间提醒用户做某事；查询、删除日程

不交给快思考

需要理解、检索、规划，或者带触发条件、有多条指令。

  • 只说感受没说指令（“热得浑身不自在”）
  • 问本车功能是什么、怎么用、为什么坏、是否正常
  • 按氛围、歌词、剧情找歌找片；让系统推荐
  • 靠描述找地点、多地点行程、去某个具体地名要多久
  • 新闻资讯；记住个人信息
  • 一次性定时动作（条件任务）、长期规则（任务大师）
  • 一句话里有两条以上指令；开放问答和闲聊

第 3 版判据里“domain 和 agent label 之间”的那张边界表，现在就是 is_fast 判据的主体；“domain 之间”的边界（如中控亮度归 carControl 还是 systemControl）交还给快思考，Jev 不再管。is_fast 只看指令类型，不看对象说得是否标准：“导航到大裤衩”的 is_fast 应为是，它的问题交给 needs_rewrite。

needs_rewrite：三种指代分开处理

指代类型例子谁处理needs_rewrite
上下文指代调完空调后说“再高一点”；“换成第二个”；“那到公司呢”快思考，带上一轮输入否
模糊指代导航到大裤衩；去鸟巢；放一首周董的歌；打开那个吹脚的大模型改写成标准名称，再交给快思考是
描述找对象杭州那个建在运河边上保留了古代码头格局的历史街区；有一部电视剧里和珅和纪晓岚斗嘴不交给快思考，第二级判给复杂导航、影视、音乐 agent不问（is_fast 已为否）

模糊指代和描述找对象的分界：常识就能还原成唯一一个标准名称的（俗称、外号、简称、昵称）归模糊指代，改写一步就够；需要检索、比较候选，或者答案不唯一的，归描述找对象，交给 Agent。判据里要用正反例把这条线写清楚。

两种判错，代价不同

错误例子后果能不能兜回来
该走 Agent，交给了快思考“空调是不是坏了” 被当成空调指令快思考可能硬落一个 domain，执行错误动作只有快思考拒识或低置信时才能升级。依赖快思考的拒识能力
该走快思考，送到了第二级“打开空调页面”多一次 Jev 调用，延迟增加第二级选“退回快思考”即可回到正路

因此 is_fast 的阈值偏向保守：拿不准的句子送第二级。在 val 上标定时，先把“该走 Agent 却交给快思考”的比例压到目标以下，再看送到第二级的比例是否可以接受。

调用量和成本

设线上没有命中规则的句子里，比例为 p 的句子交给快思考，其中比例为 r 的带模糊指代需要改写。第一级每句都调，第二级只有其余的句子调：

每句平均 Jev 输入 token ＝ T₁ ＋ (1 − p) × T₂　　每句平均 Jev 调用次数 ＝ 1 ＋ (1 − p)　　每句平均改写调用 ＝ p × r

T₁：第一级请求，三个 Noul，判据约为快思考范围、边界清单和模糊指代正反例，估 2,800 token。T₂：第二级请求，12 个 label，按 v0.5 判据中 agent 选项所占篇幅折算，估 4,000 token。第 3 版的实测值为每句一次请求、平均 7,882 token。改写调用的是通用大模型，不计入 Jev。

省下来的是 token，不是调用次数。第一级每句都要调一次，不走快思考的句子还要调第二次，所以调用次数比第 3 版略多。如果 Jev 按 token 计费，这个架构省一半左右；如果按次数计费，规则引擎能省一部分，但规则的目的是修错，不是省钱，不建议为了省调用而大量加规则。

延迟参考：评测中 409 条请求在 8 路并发下约 6 秒跑完，单次约 0.1 秒。这是 GitHub 美国机房测得的，车端链路需要另测。走第二级的句子要串行调两次 Jev；带模糊指代的句子多一次大模型改写，这是延迟最长的一段，r 需要从线上日志统计。

后续可选：快思考先跑

快思考已经有拒识能力，所以可以考虑把第一级去掉：所有句子先交给快思考，快思考拒识的才调 Jev。Jev 调用次数降到 (1 − p)，p = 80% 时每句平均约 860 token估。

好处

  • 交给快思考的句子完全不调 Jev
  • 不需要维护 is_fast 的判据

前提和代价

  • 快思考要对“空调是不是坏了”这类句子拒识，而不是硬落 domain。拒识能力有了，召回率还要测
  • 模糊指代仍然需要单独检测。“导航到大裤衩”的句式快思考能理解，它不会拒识，只会把“大裤衩”原样当成目的地。所以即使快思考先跑，needs_rewrite 这一问也省不掉
  • 不走快思考的句子多一段快思考的延迟

可以先测：测试集里有 9,000 多条 agent 侧的句子，全部送给快思考，看拒识率；再从线上日志里挑一批模糊指代的句子，看快思考是否会硬解。两项都达标，再考虑把第一级缩成只问 needs_rewrite，或者把这一问并进改写前的轻量检测。

模块之间的约定

约定内容谁维护
快思考能力清单快思考覆盖的 domain 和说法范围，以及明确不管的类型。第一级判据从它生成快思考团队
快思考输入输出输入 query 和上一轮（query、domain、槽位）；输出 domain、意图、槽位、置信度、拒识标记。拒识和置信度是兜底升级的依据快思考团队
改写约定只把模糊指代换成标准名称，其余字词不动；还原不了就原样返回并标记失败，失败的句子直接升级到第二级分流团队
规则库规则配置、正例反例、回放报告、命中日志。改动走评审，上线前必须回放分流团队，线上问题值班可提交
第一级判据is_fast、needs_rewrite、is_followup 三个问题的说明和例句分流团队
第二级判据12 个 agent label 和“退回快思考”的说明、不包含什么、例句分流团队，和各 Agent 负责人对齐
阈值is_fast、needs_rewrite、is_followup、第二级置信度、快思考置信度在 val 上标定，随判据版本发布

快思考新增 domain 时，只要不改变它和 agent 的边界，第一级判据和第二级判据都不用动。新增一个 Agent 时，只改第二级判据，以及在第一级“不交给快思考”里补一行。

评测怎么做

现有的 13,662 条评测集不用重标。“语义”sheet 的句子就是第一级的“交给快思考”，“大模型agent”sheet 的句子是“不交给快思考”，第二级的标准答案就是原来的 label。

评测看什么现有参考
第一级该走 Agent 却交给快思考的比例；该走快思考却送到第二级的比例；按阈值画曲线v0.5 判据在 409 条 dev 上的 28 选 1 结果里，跨快思考和 Agent 边界的错误有 4 条，约 1%。这是从 28 选 1 折算的，第一级要单独测
第二级只用 agent 侧样本，12 个 label 的准确率和混淆v0.5 在 dev 上剩余的 agent 侧错误集中在闲聊和影视、新闻、导航的边界
快思考拒识把 agent 侧样本送给快思考，统计拒识率和低置信率快思考已有拒识能力，召回率还没有在这批数据上测过
模糊指代needs_rewrite 的准确率；改写后快思考的理解正确率现有评测集里基本没有这类样本，要从线上日志补：地图搜索无结果、快思考槽位里出现俗称的句子
端到端第一级、快思考、第二级串起来后，每句最终去向是否正确需要快思考的输出接口

待确认

  • 快思考能否直接处理一句话里的多条指令。能的话，多条直接指令可以在第一级就交给快思考，省掉第二级和拆分；不能的话按本文设计，走中枢简单任务拆分。
  • 快思考上下文消解的范围。本文假设“再高一点”“换成第二个”“那到公司呢”这类都能处理，不在范围内的类型需要列出来，归到改写。
  • 改写用哪个大模型，延迟上限是多少。它在快思考链路上串行，直接影响这部分句子的响应时间。
  • 模糊指代的样本。需要从线上日志收集一批，才能写 needs_rewrite 的判据并标定阈值。
