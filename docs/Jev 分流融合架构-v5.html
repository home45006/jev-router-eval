Jev 分流融合架构

保留传统 NLU 分发体系作为底座，只在选定场景切入 Agentic Loop 完成任务闭环。Jev 在分发层用一次请求判定四个去向：NLU 直达、Agent 直达、慢思考、闲聊。前两者合称快思考，单轮一次命中，不经规划；慢思考进入 Loop，规划后复用快思考的业务技能执行。

V1.0 草案2026-10-26快思考能力范围：NLU3.0 v13 · 45 域

Jev 的一次请求

问题类型问什么代码怎么用
routeChoice · 4 选 1 NLU 直达：45 域能接住的单轮指令或查询。Agent 直达：意图明确、交给一个 Agent 一次就能答的请求，如用车专家、联网搜索。慢思考：子任务有依赖或跨任务约束。闲聊：没有任务目标。 读 choice 和 confidence。4 个选项时 confidence =（最高概率 − 1/4）÷（3/4）。
domainChoice · 45 + none 这句话属于哪个 NLU 域，取值即“语义”标注表的预期 domain，全部小写。 只在 route = NLU 直达时读取。交给 NLU 做 intent / slots，并与 NLU 自己的 domain 做一致性校验。
agent_labelChoice · N + none 该交给哪个 Agent，取值即“大模型 agent”标注表的 label 列。 只在 route = Agent 直达时读取，交给 Agent Hub 按注册表路由。
segment_role[i]Choice × 片段数 代码预切出的每个片段：独立、有依赖、残片。 独立片段逐条走快思考，有依赖的合成一组走慢思考，残片并入前一段。
needs_rewrite
referent		Noul + Choice 是否依赖上文才能理解；指代对象是上文候选中的哪一个。 选中则代码拼回 query；none 交生成式模型改写后回 Jev 重判。上轮是闲聊时，追问一律跟随闲聊。

官方文档建议把系统需要的问题放进同一次请求，由代码只读与去向相关的答案：同一请求里的问题并行判定，多加问题对时延影响很小。所以 domain 和 agent_label 不必等 route 出结果再问，一次请求就能拿到快思考需要的全部标签。

交界域怎么分

交界建议例
help · intelligent_car_info
对 用车 Agent		 查一个数值或状态走 NLU；要解释原因、给处理建议走 Agent 直达到用车 Agent。 “还剩多少油”→ NLU；“胎压灯亮了怎么办”→ 用车 Agent
task_setting
对 条件任务 / 任务大师		 按已有定义，一次性的条件任务和周期性的任务大师都由大模型 Agent 理解，云端大脑图把两者放在慢思考。建议 Jev 把这类 query 判给慢思考，task_setting 不再作为入口。 “上车后自动开启空调”→ 慢思考
agent_task · app_agent 单个明确的代办或应用内操作走 Agent 直达；带多个约束或要串联其他任务时走慢思考。 “帮我点两杯瑞幸凉少糖美式”→ Agent 直达
travel_plan 多日行程规划天然是多步任务，建议走慢思考。若 NLU 域内技能已能一次产出行程，可暂留 NLU 直达。 “帮我规划北京四天的行程”→ 慢思考

需要先确认的六点

Agent 标签全集

图里的用车 Agent、400 客服、联网查询、三方 Agent 只是示例。agent_label 的选项需要按“大模型 agent”标注表定稿，每个标签对应 Agent Hub 里一个已注册的 Agent 或 Tool，另加 none。

45 选 1 的准确率

一个 Choice 最多支持 255 个选项，45 个没问题，但官方提示模型偏向排在前面的选项，中文准确率也偏低。如果实测不够，改成两层：先判五个大组，再判组内 domain，两问仍放在同一次请求里。

两个 domain 谁说了算

Jev 和 NLU 各给一个 domain。建议一致时直接执行；不一致时以置信更高的为准，或车控类以 NLU 为准。不一致率本身是监控指标，能最早发现 Jev 或 NLU 哪边漂了。

800ms 的预算

快思考的路径是 ASR、Jev、NLU、执行串行。可以让 NLU 和 Jev 同时起跑，route 不是 NLU 直达时丢弃 NLU 结果，大部分流量就省掉一次等待。代价是 NLU 调用量增加，需要实测 Jev 在车上的时延再定。

条件任务的归属

云端大脑图把条件任务和任务大师放在慢思考，NLU 清单里又有 task_setting。两边要统一：本稿按慢思考画，如果标注表里它们是 Agent 直达的 label，就移到快思考。

部署与修复通道

官方只提供云端 API，没有提到端侧或私有化部署，量产前要确认网络、时延和合规。干预表、问题定义和阈值都放云端配置中心，判错时分钟级止血、小时级根治，详见 V0.4 分流方案。
