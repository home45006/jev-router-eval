Jev 分流融合架构 · V6 分层判定

本架构只负责分发和落域，不负责业务。大部分 query 是单轮、能被 NLU3.0 直接执行的指令，所以判定分两层：第一层每句都问，只判“是不是快思考”，是就直接落 NLU3.0 返回；第二层只在不是快思考时才问，判 Agent 直达、慢思考、闲聊和安全。决策模型可选 Jev 或自部署的 StartLux，两者接口相同。

⚠ 已搁置，未实现（2026-10-29）V6 · 2026-10-29两层判定 · 多数流量只走第一层NLU3.0 · 19 个入口域Agent 直达 · 10 个决策模型：Jev / StartLux

分层判定架构

为什么分层

单次判定版每句都问 7 道题，其中 Agent 标签、片段角色、安全这几道只对少数非快思考的句子有用。分层后，占多数的快思考句子只付第一层的钱和时间。下表是 2026-10-29 用“把副驾车窗关上一半”实测（取两次中较快的一次；第一层用现有的 domain + has_nickname 代替，is_fast 是新题，预计再加约 600 tokens）。

请求Jev（jev-1.14.0，公网）StartLux（v1-9B Q8，自部署实例）
单次判定（6 题一起）691 ms · 6,558 tokens5,424 ms · 4,347 tokens
第一层草案（domain + has_nickname）355 ms · 2,334 tokens1,707 ms · 1,432 tokens
第二层草案（is_unsafe + route + agent_label + needs_context）521 ms · 4,525 tokens3,506 ms · 2,915 tokens

按快思考占比 f 估算每句平均 token：单次判定约 6,600；分层约 3,000 + (1 − f) × 4,500。f = 70% 时约 4,350，省约三分之一；f = 50% 时约 5,250。代价是非快思考的句子要串行判两次，见下文时延。

两层各问什么

层问题类型作用
第一层每句都问is_fast（新）Noul整句是不是 NLU3.0 能直接执行的指令：车控、按名点播和播放控制、电话微信、导航去具名地点、车家、生成、计算，含多意图和同功能多参数。带时间触发、要推断、要查询的都不算
domainChoice · 19 + 非入口校验 NLU3.0 落的域（NLU3.0 不出置信度，这是唯一依据）；“非入口”最高时不走快思考
has_nicknameNoul俗称要先还原（导航去大裤衩），还原后重判第一层
needs_contextNoul，有上一轮时才问“再高一点”这类接着上一轮的指令照样可以是快思考；上一轮是 Agent 或闲聊时，它决定第二层是否直接跟随
第二层非快思考才问is_unsafeNoul违法有害 → 安全拒答。快思考句子不过这道题，靠干预表敏感词兜底
routeChoice · 4 选 1慢思考 / Agent直达 / 闲聊 / 退回快思考。“退回快思考”给第一层漏判的指令一个回去的路
agent_labelChoice · 12 + none交给哪个 Agent；也用于 NLU3.0 落非入口域时确认回流对象
segment_role[i]Choice × 片段数多段时每段的角色：有依赖 / 同一任务 / 独立指令 / 独立 Agent 类 / 残片
needs_contextNoul第一层没问过时在这里补问

每道 Choice 仍把兜底选项放第一（第二层 route 的慢思考、domain 的非入口、agent_label 的 none、segment_role 的有依赖）。is_fast 的阈值偏严：判错成快思考的代价（错误指令被执行）高于判错成非快思考（多走一层）。

第一层没通过的原因（is_fast 低、domain 非入口、NLU 结构不完整、域不一致、落非入口域）都带进第二层，第二层据此判断；NLU3.0 结果只解析一次，两层共用。

已定与待定

已定 · 分层

第一层每句都问、只判快思考，通过即返回；第二层只在非快思考时问。两层共用一次 NLU3.0 解析。

已定 · 归属和出口

NLU 直达 19 个入口域；10 个 Agent 直达；慢思考只收跨能力有依赖和快思考落不了的；闲聊；安全拒答；落域被拒改落慢思考一次。

已定 · 决策模型

Jev 和 StartLux 接口相同，两层都可用任一个；用测试页的对比模式在评测集上选型。

待定 · is_fast 判据和阈值

新题，要写判据并在 val 上标定 T_FAST；重点是带触发条件的车控、冷门设置项、按描述点播这几类边界。

待定 · 第二层预取

上一轮是 Agent / 慢思考 / 闲聊或多段句时两层并发，是否开、对哪些情况开，看线上快思考占比和时延。

待定 · 快思考句子的安全

只靠干预表敏感词是否足够；不够时把 is_unsafe 挪进第一层（约 +300 tokens）。

待定 · StartLux 部署

当前实例逐题串行，第一层约 1.7 s、两层约 5 s，满足不了 800 ms；需换 vLLM / Prism、更强 GPU 或多槽并行。权重 CC BY-NC 4.0，商用需授权。

待定 · NLU3.0 接口

批量调用、各 intent 必填槽位表、接不住时是否固定落 other。

待定 · 部署与合规

Jev 只有云端 API；配置中心承载两层判据、阈值、干预表和回流表。

本架构的边界：输入是 ASR 文本、会话状态和车辆状态，输出是去向和落域结果。当前生效的单次判定版（V2.0）在 docs/Jev 分流融合架构-v6.html，V1.0 在 docs/Jev 分流融合架构-v5.html。详细规则需按本稿更新 design/Jev 分流详细设计；实测数据见 webdemo /v5 测试页。NLU 域清单取自《车机 NLU3.0 大模型支持 Domain 清单（v13）》。
