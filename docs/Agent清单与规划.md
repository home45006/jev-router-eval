说明：

- “v25 训练条数”是 NLU 训练集的分布，不是线上流量，只能粗看需求量。上线后以“命中但未上线”的日志计数为准（见第三节）。
- 回退只用于信息类：出行规划的问题联网搜索能先答个大概；其余是执行类任务，联网搜索办不了，所以落慢思考。
- `/v5` 测试页“设置”里可以把任一 Agent 切成 on，模拟它上线后的分流。

## 二、和旧标签的对应

| 旧标签（判据 v3.2） | 现在 |
|---|---|
| 新闻、天气 | 并入联网搜索 |
| 音乐、影视 | 说出名字或风格的点播是 A 类 `music`、`video`，NLU 直达；歌曲影视问答和推荐归联网搜索 |
| 自适应车控 | 只说感受（“车里好热啊”）是 A 类 `intelligent_car_scenario`，NLU 直达 |
| 用车专家 | 保留，但查车况（油量、胎压、门窗状态）是 A 类 `intelligent_car_info`，NLU 直达；用车专家只管功能和故障问答 |
| 出行导航 | 导航去说得出名字的地点仍是 `navigation`，NLU 直达；找店交美团；多地点路线和行程交出行规划 |
| 代办点单 | 点单、订房并入美团；在第三方 App 里操作归应用调用 |
| 任务大师 | 不变，已上线 |
| 记忆、400客服 | 不变，规划中 |

## 三、开发顺序建议

已上线：联网搜索、美团、用车专家、任务大师（2026-11-02）。规划中的按下面顺序：

1. **记忆**：已有业务标签数据（`data/一阶分发业务labels/01_记忆agent`），也没有回退可用，命中后只能落慢思考，优先补。
2. **出行规划**：已有业务标签数据（`02_出行导航agent`）；未上线时联网搜索能先顶上。
3. **应用调用**、**内容娱乐**：依赖车机端第三方 App 和内容源接入，按合作进度排。
4. **车外视觉**、**AI创作**：依赖摄像头和生成能力，训练量最少，最后排。

排期前先看线上日志：分流结果里 `intended`（Jev 判给的 Agent）和实际去向不一致的记录，就是“命中但未上线”的请求，按 Agent 计数即可。
