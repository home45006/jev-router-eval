# 座舱 Agent 大脑 v7 原型详细设计

- 版本：V1.3 · 2026-11-04（V1.3：模型定为 DeepSeek V4 Flash 非思考模式，不做模型对照；写明通过线口径；任务大师加“立即触发”；体验脚本 7 → 9 个；补 trace 回放、任务调试接口；V1.2：确定型业务 Agent 改为按 Command 协议封装的 19 个模拟 tool，灰区改由执行器前置条件实现；V1.1：原型只验证选对业务 Agent、填对参数，以体验智能交互为目的，不考虑简单车控时延和大模型开销）
- 依据：`docs/座舱 Agent 大脑架构-v7.html`（V7.0）；参考 `doubao/荣威家越07 豆包座舱语音架构调研.html`
- 框架：AgentScope 2.0.9（Python 3.11+）。本文用到的类、钩子和事件字段都已在 2.0.9 上核对过（见附录 A）
- 配套：`agentscope/开发计划-v7.md`；`agentscope/Command 协议 Tool 封装设计-v1.html`（第 6 节的完整版）

## 1. 原型的目的

v7 去掉了 Jev 前置分流和 NLU3.0，所有句子都交给 Agent 大脑。原型有两个目的：

1. **验证**：大脑能不能**选对业务 Agent、填对参数**。这是原型唯一要用数据回答的问题。
2. **体验**：让用户亲手体验 Agent 大脑的交互，感觉到座舱语音是有智能的，不再是“一句一个命令”（要体现的智能行为见第 10 节）。

| 验证项 | 怎么量 | 通过线（原型阶段） |
|---|---|---|
| 选对业务 Agent | 每轮实际调用的工具和期望是否一致：推理型 Agent 看工具名；Command tool 看 tool 和协议指令名都对（该调的都调了，不该调的没调；该直接回答的没调工具） | 单轮 ≥ 95% |
| 填对参数 | Command tool 按协议槽位逐项断言（Device、Position、Number、Keyword、Name…）；推理型 Agent 断言 task 里的关键信息 | 单轮 ≥ 90% |
| 多轮里仍然选对、填对 | 多轮场景每一轮都按上面两项判，整段全对才算完成 | 整段完成率 ≥ 85% |

**通过线口径**：单轮两项按“单轮基础 + 难例”两个集合计算（12.3），取 3 次回放的均值，同时报告“3 次都对”的比例；协议话术集是从协议示例自动生成的，比较好答，单独报告、不计入通过线；多轮按多轮集整段计算。

**不在原型范围内的**：简单车控的时延、大模型的 Token 开销。不设指标，不做优化实验。模型固定用 DeepSeek V4 Flash 非思考模式，不和其他模型对照（10.3）。trace 里照常记录耗时，只用来排查问题。

### 范围

| 做 | 不做（用模拟或留接口） |
|---|---|
| 文本进、事件流出的大脑服务（AgentScope Agent） | 端侧拒识、ASR、TTS、全双工：页面上打字代替说话，播报只显示文字 |
| 5 个确定型业务 Agent：按 Command 协议封装的 19 个模拟 tool + 模拟执行器 | 真实车机执行：Command 由模拟执行器执行，下行指令只在页面显示 |
| 4 个已上线推理型业务 Agent 的适配 | 未上线的 7 个推理型 Agent：只在注册表里登记，默认关闭 |
| 彩 / 灰 / 黑三级权限、下单确认流程、安全拦截 | DMS / OMS 视觉、长期记忆中间件（第二期） |
| 会话、多音区（每个座位一个会话） | Redis 持久化（接口留好，原型用内存） |
| /v7 体验页、体验脚本、场景评测集、评测脚本 | 时延优化、Token 开销统计、生产部署、灰度、监控告警 |

- 原型的 Python 包叫 `cockpit_brain`，不叫 `agentscope`；

## 3. 总体流程

```
页面 / 评测脚本
   │  POST /v7/chat {session_id, seat, text}
   ▼
orchestrator.on_utterance
   ├─ safety.check_input ──命中──▶ 固定拒答，结束
   ├─ session.load(session_id, seat)            取大脑和子 Agent 的 AgentState
   ├─ vehicle.snapshot()                        当前车辆信号
   ├─ brain = build_brain(session, snapshot)    每轮重建
   ├─ async for ev in brain.reply_stream(UserMsg(name=f"seat:{seat}", content=text)):
   │      TextBlockDeltaEvent   → text_delta（送页面，正式版送 TTS）
   │      ToolCallStartEvent    → tool_start（可触发预播报）
   │      ToolResultEndEvent    → tool_end（结果摘要）；Command tool 另出 command、action 事件
   │      RequireUserConfirmEvent → confirm_required，流暂停，等 /v7/confirm
   │      ReplyEndEvent         → done
   ├─ safety.check_output（播报前）
   └─ session.save(...)
```

Command tool 执行后，下行指令以 `command` 事件、车辆状态变化以 `action` 事件发给页面，下行指令面板和车辆面板据此刷新。

## 4. 车辆模拟器和 Context

### 4.1 VehicleState

```python
class Seat(BaseModel):
    heat: int = 0            # 0–3 档
    vent: int = 0
    massage: bool = False
    recline: int = 100       # 靠背角度，100 为标准

class VehicleState(BaseModel):
    speed_kmh: float = 0
    gear: Literal["P", "R", "N", "D"] = "P"
    battery_pct: int = 80
    outside_temp: float = 18
    cabin_temp: float = 26
    ac: dict                  # {on, temp_by_zone, fan, mode, recirc}
    power_on: bool = True
    windows: dict[str, int]   # 主驾 / 副驾 / 左后排 / 右后排 → 开度 0–100（位置名与协议 Position 一致）
    sunroof: int; curtain: int; backdoor: int    # 开度 0–100
    doors_locked: bool
    seats: dict[str, Seat]
    lights: dict              # 阅读灯、氛围灯颜色亮度
    fragrance: str | None
    tire_pressure: dict[str, float]
    warnings: list[str]       # 仪表报警，例如“左后胎压低”
    media: dict               # {source, playing, title, artist, volume}
    nav: dict                 # {active, destination, eta_min}
    phone: dict               # {in_call, contact, bluetooth}
    network: bool = True
    switches: dict[str, bool] # 通用开关状态，键为“设备/位置”，供 Device.Open / Close
    location: dict            # {city, lat, lng, poi}
```

车辆状态只由 Command 执行器修改（6.5），`snapshot()` 给 Context 用。页面可以直接改车速、档位、上电、蓝牙、网络、车窗、报警等，用来测前置条件和“有点吵”这类需要看状态的句子。

### 4.2 Context 渲染

`ContextMiddleware.on_system_prompt(agent, current_prompt)` 每次推理前把车辆状态渲染成一段短文本拼到系统提示词末尾（2.0.9 的钩子签名，见附录 A）：

```
【车辆状态 2026-11-04 15:20 周三 · 北京市朝阳区】
行驶中 62km/h，D 挡；电量 71%；车外 12℃，车内 24℃
空调开 · 主驾 24℃ 副驾 24℃ · 风量 3 · 外循环
车窗：主驾开 15%，其余关；天窗关
媒体：QQ音乐 播放中《晴天》周杰伦 音量 28
导航：去 首都机场T3，剩 35 分钟
报警：无
说话人：右后排
```

只放大脑做判断需要的信号，控制在 300 字以内，放在提示词末尾。Context 是大脑“看得到车”的唯一来源，第 10 节里大部分智能行为都依赖它，渲染格式改动后要全量回放场景集。

## 5. Agent 大脑

### 5.1 构造

```python
def build_brain(sess: Session, snap: VehicleState) -> Agent:
    tools = command_tools(sess)                                 # 19 个 Command tool，第 6 节
    tools += [make_subagent_tool(spec, sess) for spec in registry.online()]   # 第 7 节
    tools += [FunctionTool(meituan_place_order, permission=ASK)]               # 下单确认，第 8.3 节
    return Agent(
        name="agent_brain",
        system_prompt=BRAIN_PROMPT,
        model=deepseek_flash(),                                 # V4 Flash 非思考，见 10.3
        toolkit=Toolkit(tools=tools),
        middlewares=[ContextMiddleware(snap, sess.seat), CommandPermissionMiddleware()],   # 需确认的指令，8.1
        state=sess.brain_state,
        react_config=ReActConfig(max_iters=cfg.max_iters),     # 默认 8
    )
```

每轮重建 Agent、从会话恢复 state，不在会话之间共享实例。v7 不再需要 `TurnStatus`（continue / suspend / end）：每句都进大脑，没有“交回分流”这回事，所以去掉结构化输出，大脑直接输出播报文本。

### 5.2 系统提示词

四段，前三段固定，第四段由 ContextMiddleware 追加：

1. **角色和原则**：你是车上的语音助手，像一个懂车、记性好的副驾。先办事再说话；播报一两句，口语，不念列表符号；根据车辆状态推断的要说出理由（“车窗开着，先帮你关上”）；信息不够时只问一个最关键的问题，能合理默认的不问；做不到的说清楚原因并给替代办法，不说“听不懂”。
2. **工具使用规则**（v6 判据里的归属规则搬到这里）：
   - 车控按 tool 边界选：打开 / 关闭某个设备 → `switch_device`；空调温度风量风向、香氛 → `climate`；座椅 → `seat`；车窗天窗遮阳帘背门雨刮门锁后视镜 → `body`；氛围灯和车灯 → `lighting`；驾驶、能量、充电设置 → `drive_energy`；问车况（电量、续航、胎压、门窗） → `vehicle_query`
   - 只说感受（热、冷、闷、吵、暗）→ 先看车辆状态，再组合上面的原子指令；没有“场景”指令可用
   - 播放 → `media_play`；下一首、暂停、播放模式 → `media_control`；音量、屏幕、蓝牙、HUD、语音设置 → `system_settings`；打开应用或设置页 → `open_page`
   - 列表里的“第几个”：用上一轮查询结果里该项的名称直接下发指令，没有“选择第几个”的指令
   - tool 返回的 status 不是 Succeed：参考 reply 说明原因并给替代办法；ParamError 按提示改正后重试一次
   - 新闻、天气、股票、航班、限行、计算、百科、歌曲影视知识 → `web_search`
   - 找餐厅、酒店、景点、店铺，点外卖、咖啡，订房 → `meituan`；真正下单 → `meituan_place_order`
   - 本车功能怎么用、报警灯什么意思、用车常识 → `car_expert`
   - 定时、延时、到达触发、每天每周的规则 → `task_master`；“半小时后关空调”= 现在不动，交给任务大师
   - 说得出名字的地点 → `navigation`（`Navigation.SearchPoi`）；找附近、沿途某类地点 → 先 `nav_query` 查再让用户选；要看评价、人均或要下单的找店 → `meituan`；俗称先还原成标准名称（大裤衩 → 中央电视台总部大楼）
   - 打电话：名字可能重名或不全时先 `contact_query`，确定后 `phone`
   - 几件事互不依赖时一次发出多个工具调用；后一件要用前一件的结果时，等结果回来再调
   - 闲聊、讲故事、情绪表达：直接回答，不调工具
3. **车企规则**：`vehicle/knowhow.py` 的文字，含 6 条场景指令背后的动作组合（6.6）。
4. **车辆状态**：见 4.2。

提示词放在 `brain/prompt.py`，评测时可以按版本号切换，报告里记录用的是哪一版。

### 5.3 多轮、多音区和会话

- 会话键：`{vehicle_id}/{seat}`。四个座位各自一个会话，互不干扰；车辆状态共享。
- `Session` 里存：大脑的 `AgentState` JSON、各子 Agent 的 `AgentState` JSON（键 `{会话}/{agent_name}`）、最近一次活跃时间、轮数。
- 生命周期：空闲超过 `SESSION_IDLE_S`（默认 120 秒）、轮数超过 `SESSION_MAX_TURNS`（默认 30）、或用户说退出词（“没事了”“退下吧”）时清空。这些兜底在 `session.py` 里做，不靠大脑判断。
- 上下文长度：AgentScope 自带压缩（`on_compress_context`）。原型先用默认配置，体验脚本里观察长会话压缩后会不会忘掉前面的任务和偏好。

## 6. 确定型业务 Agent：Command 协议 tool

完整设计见 `agentscope/Command 协议 Tool 封装设计-v1.html`（以下简称“封装设计”），本节是摘要和落地约定。

### 6.1 依据和原则

依据《梧桐语音 Command 协议》V1.1.4（`agentscope/command协议/1792545950625_梧桐指令清单-内部.xlsx`）：1125+ 条目、743 个不重复指令名、9 个 `Native://` 查询接口、39 个执行结果状态码。

- **入参用协议原样**：每个 tool 的入参是“一条协议指令名 + 协议槽位参数”，参数名照抄协议（包括 `KeyWord` / `Keyword` 并存、`Tyep` 这类拼写），保证生成的指令车端认得；
- **出参用协议状态码**：返回协议状态码和按状态码选出的回复语，大脑据此解释原因、给替代办法；
- **按能力分 19 个 tool**，归到 5 个确定型业务 Agent 加 AI 创作下面。不给每条指令单独建 tool（约 680 个，大脑选不过来），也不建一个通用 `execute_command`（一张近 700 条的大表）；
- **tool 内部不调大模型**：校验 → 前置条件 → 状态模拟 → 状态码和回复语，结果确定、可复现，便于判断参数填得对不对；
- **一次调用一条指令**，几件事就并行发几个调用；全部 `is_concurrency_safe=True`；
- tool 的签名、枚举、描述都由协议目录**自动生成**，协议更新后重跑脚本即可。

### 6.4 tool 接口

```python
async def climate(
    command: Literal["ACCtrl.OpenMode", "ACCtrl.CloseMode", "ACCtrl.SetTemperature", ...],
    params: dict[str, str] = {},
) -> str:
    """空调和香氛：温度、风量、风向、空调模式、新风、预约空调、香氛类型和浓度。
    开关空调本身用 switch_device（Device=空调）。
    - ACCtrl.SetTemperature 空调温度调节
        Area 位置：主驾|副驾|前排|左后排|右后排|后排|所有
        Direction 方向：调高|调低 · Mode 模式：档位|温度 · Number 数值
        例：主驾空调调到20 → {"Area":"主驾","Mode":"温度","Number":"20"}
    ...（由 command_catalog.json 生成）"""
    return await executor.run("climate", command, params, ctx=current_turn())
```

- `command` 是枚举，省掉 `Command://Tinnove.` 前缀；`params` 是协议槽位，可空的可以不填；
- 描述自动生成：每条指令的功能、参数、取值、一个话术示例。原型不考虑大模型开销，描述写全；超过 60 条指令的 tool 按小类分组；
- 描述第一段写清和相邻 tool 的边界（开关空调 `switch_device`、调温度 `climate`；播放 `media_play`、下一首暂停 `media_control`；音量在 `system_settings`；查车况 `vehicle_query`、问功能怎么用交用车专家），这是混淆表最先要看的地方。

返回（JSON 字符串）：

```json
{"command": "Command://Tinnove.ACCtrl.SetTemperature",
 "params": {"Area": "主驾", "Mode": "温度", "Number": "20"},
 "status": "Succeed", "reply": "主驾温度调到20了",
 "changes": [{"path": "ac.temp.主驾", "before": 24, "after": 20}]}
```

查询类 tool 返回 `{"interface": "Native://Tinnove.Navigation.SearchPOI", "code": 0, "items": [...]}`。参数不合法返回 `{"status": "ParamError", "message": "Area 取值应为 …，收到“后座”"}`，大脑可以改正后再调一次（评测仍记为填错）。

### 6.5 模拟执行器

| 环节 | 做法 |
|---|---|
| 协议目录 | `agentscope/scripts/gen_command_catalog.py` 读协议 xlsx，生成 `commands/command_catalog.json`：指令名、模块、domain + intent、功能、参数（名称、说明、取值枚举）、话术示例、状态码 → 回复语、所属 tool。分类规则在 `commands/command_categories.yaml`。该 xlsx 用 openpyxl 读会报样式错误，脚本直接解析 xml |
| 校验 | 指令属于该 tool；参数名是协议里有的；有枚举的取值在枚举里；Number 是数字 |
| 前置条件 → 状态码 | `commands/preconditions.py` 规则表，见 8.1。**灰区由这一层实现**，和真车行为一致 |
| 状态模拟 | ① 精确模拟约 40 条高频指令（空调温度风量、座椅加热通风按摩位置、车窗天窗遮阳帘背门、音量、氛围灯、媒体播放、导航、电话），维护数值和范围，返回 Already、PartSucceedMax / Min、OutOfRange；② 通用开关：所有 Open / Close 和 `Device.Open / Close` 按（设备, 位置）记开关状态，重复操作返回 Already；③ 通用设置：其余 SetXxx 记最后一次设置的值，返回 Succeed |
| 回复语 | 取该状态码第一条候选（`||` 分隔的固定取第一条，保证可复现），填好 `$@Position$`、`#@Name#` 等占位 |
| Native 查询 | `commands/native_mock.py`：约 50 个 POI（家、公司、几个城市的地标、餐厅、加油站、充电站、停车场）、约 20 个联系人（含两个“老王”、只有号码段的）。`Center` 参数按名称找中心点，按距离排序 |
| 车型配置 | `vehicle/profile.py`：模拟车型有哪些配置（后排空调、天幕、尾翼、HUD…），没有的返回 NotFound |
| 故障注入 | 体验页可以指定“下一次某指令返回某状态码”（NotNet、BluetoothDisconnected…），演示大脑怎么解释 |
| 下行 | 每次成功执行生成协议原样的 `Command://Tinnove.ACCtrl.SetTemperature?Area=主驾&Mode=温度&Number=20`，以 `command` 事件下发，体验页“下行指令”面板逐条显示 |

### 6.6 车企规则和隐含车控

“好热”“有点吵”这类只说感受的句子，由大脑看 Context 选指令，再调原子指令（`climate`、`body`、`switch_device`…）。协议里的 6 条场景指令不封装，它们背后的动作组合（太吵、闷、吹风、看星星、静静、暴雪）整理成文字写进系统提示词第 3 段，作为大脑推断的参考而不是硬规则，例如：

```
- 说吵：车窗开着先关窗；车窗都关着再把音乐调小
- 说闷：开外循环或新风；车速不高时可以开一点车窗
- 说热：空调开着就降 2℃，没开就打开空调设 24℃；只调说话人所在位置
```

具体定义要从车控团队拿到（开发计划依赖项）。只给方向不给数值时（`Direction=调高`），执行器按协议默认步长处理（温度 1℃、风量 1 档）。

### 6.7 接真车

```python
class CommandExecutor(Protocol):
    async def run(self, tool: str, command: str, params: dict, ctx: TurnCtx) -> CommandResult: ...
```

- `SimCommandExecutor`：原型默认，即 6.5；
- `CarCommandExecutor`：把同样的 Command URI 发给车机，等车端回传状态码；Native 查询走车端反查。tool 和大脑不变。正式版可以用 AgentScope 的外部工具机制（`RequireExternalExecutionEvent` / `ExternalExecutionResultEvent`）让车端执行后回传。

原 NLU 执行层的 `(domain, intent, slots)` 接口不再需要：Command 协议本来就是 NLU 结果经语义转换后的下行格式，tool 直接产出它。

## 7. 推理型业务 Agent

### 7.1 注册表

```python
@dataclass
class AgentSpec:
    name: str                 # 工具名，例如 "meituan"
    title: str                # 中文名，给页面看
    description: str          # 给大脑看的工具说明：能做什么、什么时候用
    system_prompt: str
    tools: list[FunctionTool]
    status: Literal["online", "planned", "off"]
    max_iters: int = 4
    backend: Literal["agent", "service"] = "agent"   # service：已有服务，直接 HTTP 调
```

只有 `online` 的才注册成大脑的工具；页面可以临时切换 on / off，模拟某个 Agent 上线或下线。`planned` 的 Agent 不注册，大脑看不到就不会调，用户提到时大脑说暂不支持，同时在 trace 里记一条 `unsupported`（从播报文本和提示词约定的标记里识别），作为排期依据。

### 7.2 包装成工具

沿用 `.claude/skills/agentscope-cockpit/examples/brain_demo.py` 的 `make_subagent_tool`：工具只有一个 `task: str` 参数，子 Agent 每次按会话恢复自己的 state，跑完存回。描述末尾统一加一句“task 要写清楚任务和必要上下文，子 Agent 看不到你和用户的对话”。

`backend="service"` 的 Agent（已有服务、不在本进程里跑 AgentScope）也包成同样签名的 `FunctionTool`，内部发 HTTP 请求，把 session_id 一并带上，由对方服务维护多轮状态。

### 7.3 四个已上线 Agent 的原型做法

| Agent | 原型做法 | 接真实服务时 |
|---|---|---|
| 联网搜索 `web_search` | 复用 `webdemo/search_deepseek.py` 的 `DeepSeekSearch`（DeepSeek 自带联网搜索，一次请求内自己搜、自己写答案），包成 `backend="service"` 工具；没有密钥时用 `MockSearch` | 已是真实能力 |
| 美团 `meituan` | 子 Agent + 三个模拟工具：`search_poi(keyword, near, price_max, sort)`、`get_items(poi_id)`、`draft_order(poi_id, items)`。数据是 `agents/data/meituan_mock.json` 里的固定店铺和菜单。只出订单草稿，不下单 | 换成美团 Agent 服务；下单仍由大脑的 `meituan_place_order` 确认后调用 |
| 用车专家 `car_expert` | 子 Agent，知识来自一份本车手册摘要（报警灯、常用功能设置路径），放在系统提示词里；大脑调用时把 Context 里的报警和胎压写进 task | 换成用车专家服务 |
| 任务大师 `task_master` | 子 Agent + 工具 `create_task(trigger, action, repeat)`、`list_tasks()`、`delete_task(id)`；原型里有一个进程内定时器，到点后以 `seat:system` 身份把动作文本（如“关闭空调”）送进大脑执行，页面上能看到触发；调试用 `POST /v7/tasks/{id}/fire` 立即触发，验收和演示不用真等 | 换成任务大师服务，触发回调走同一入口 |

真实服务的接口文档拿到后，只改各自的 `agents/*.py`，大脑和注册表不动。

## 8. 安全和权限

### 8.1 三级权限

| 区 | 原型实现 |
|---|---|
| 彩 | tool 注册时 `permission=PermissionDecision(behavior=ALLOW)` |
| 灰 | **执行器的前置条件规则**返回协议状态码（`PrecondSpeedNotSupported` 等），和真车行为一致；回复语和原因交回大脑，大脑解释并给替代办法 |
| 需确认 | 同一个 tool 里既有直接执行的指令也有要确认的指令（如 `phone` 里的 `DialContact` 和 `BcallCall.DialContact`），所以不能按 tool 设权限。`CommandPermissionMiddleware.on_check_permission` 从 `input_kwargs["tool_input"]["command"]` 取指令名，命中确认清单就返回 `PermissionBehavior.ASK`，走 8.3 的确认流程。确认清单：`EcallCall.DialContact`、`BcallCall.DialContact`（紧急、道路救援）、`APP.Uninstall`、`meituan_place_order` |
| 黑 | 不注册：黑区指令不进任何 tool 的枚举，黑区设备不进 `switch_device` 的 Device 枚举（6.3）。用户提到时大脑说明“驾驶控制请交给智驾或手动操作” |

前置条件规则（`commands/preconditions.py`，可在体验页查看）：

| 条件 | 适用 | 状态码 |
|---|---|---|
| 车辆未上电 | 车控、驾驶控制类全部指令 | `PrecondPowerNotSupported` |
| 车速 > 0 | 主驾座椅位置、零重力座椅、背门、车门解锁、部分驾驶设置 | `PrecondSpeedNotSupported` |
| 非 P 挡 | 背门开启、充电设置 | `PrecondNotSupported` |
| 车速 > 120km/h | 车窗、天窗开度大于 30% | `PartSucceed`（只开到 30%） |
| 非主驾发起 | 驾驶控制、部分仅主驾可操作的设置 | `PrecondUserNotSupported` |
| 车型无此配置 | 由 `vehicle/profile.py` 决定 | `NotFound` |
| 空调未开 | 调风量、风向 | `NotAC` |
| 蓝牙未连接 | 打电话、同步通讯录 | `BluetoothDisconnected` |
| 无网络 | 在线音乐、视频、小程序 | `NotNet` |

### 8.2 内容安全

- 输入：`safety.check_input(text)` 在进大脑之前执行。原型用敏感词表（`safety_words.txt`）加正则，命中直接返回固定拒答，不调模型；
- 输出：大脑最终文本在送播报前再过一次同一张词表，命中则换成兜底话术并记录；
- 正式版换成内容安全服务，接口不变。

v6 的 `is_unsafe` 题和干预表不再使用。

### 8.3 下单确认

美团子 Agent 只出订单草稿（店、商品、金额、送达地址），返回给大脑。大脑复述后调 `meituan_place_order(draft_id)`，这个工具注册为 `PermissionBehavior.ASK`：

1. AgentScope 产出 `RequireUserConfirmEvent`（字段 `tool_calls`），流在这里停住；
2. orchestrator 把它转成 `confirm_required` 事件发给页面，并把大脑 state 存回会话；
3. 用户点“确认 / 取消”或说“确认”，页面调 `POST /v7/confirm {session_id, seat, confirmed}`；
4. orchestrator 重建大脑，用 `UserConfirmResultEvent(reply_id=..., confirm_results=[ConfirmResult(confirmed=..., tool_call=...)])` 调 `reply_stream` 续上。

把确认放在大脑而不是子 Agent，是因为子 Agent 被包成普通工具后，它内部的确认事件传不到外层（brain_demo 里已注明）。

## 9. 编排器和事件

### 9.1 对外事件（ndjson，每行一个）

| type | 字段 | 来源 |

### 9.2 trace

### 10.2 体验脚本

`demos/*.yaml`，每个脚本是一段带初始车辆状态的多轮对话，体验页里一键加载、逐句播放或让用户接着自由说。首批：

### 10.3 模型选择

大脑和子 Agent 都用 **DeepSeek V4 Flash（`deepseek-flash`）非思考模式**（AgentScope 技能里已验证过的配置）：

```python
DeepSeekChatModel(model=cfg.deepseek_model, parameters=DeepSeekChatModel.Parameters(thinking_enable=False))
```

- 不和其他模型、也不和思考模式做对照；评测和演示都只用这一个模型；
- 选错、填错只靠改提示词、tool 描述和分组解决，不靠换模型；
- 联网搜索沿用 `webdemo/search_deepseek.py` 的配置。

### 11.2 /v7 体验页

体验优先，界面像车机而不是调试工具；调试信息收在右侧，可以折叠。三栏：

- 左：对话区。选择说话座位（主驾、副驾、左后排、右后排）；播报逐字出现；大脑调用工具时先显示一句过渡（“正在帮你找附近的川菜馆”）；结果卡片（店铺列表、导航路线、订单）；下单确认弹窗。顶部可以加载体验脚本。可选用浏览器语音输入和朗读，让体验更接近车上。
- 中：车辆面板。空调、座椅、车窗、灯光、媒体、导航的示意图，本轮改动的部件高亮并标出前后值；可以直接改车速、挡位、上电、蓝牙、网络、车窗、报警，用来演示状态消歧和前置条件。下面是“下行指令”面板，逐条显示本轮下发的 `Command://Tinnove.*` 和状态码；故障注入、定时任务列表和“立即触发”按钮也在这里。
- 右：大脑在想什么（可折叠）。本轮调用树：大脑 → 工具 / 子 Agent → 子 Agent 的工具，每个节点的参数和结果；权限判定（放行、拒绝及原因、待确认）。另有业务 Agent 开关、会话信息、按 turn_id 回放 trace。

另有“批量评测”标签页：跑场景集，显示逐条判定和按标签的选对率、填对率，点一行展开调用树。

## 12. 场景评测

评测只判两件事：**选对业务 Agent**、**填对参数**。

### 12.1 场景格式（`scenarios/*.jsonl`）

```json
{
  "id": "multi-meituan-02",
  "tags": ["多轮", "美团", "指代"],
  "vehicle": {"speed_kmh": 40, "gear": "D"},
  "turns": [
    {"seat": "主驾", "text": "附近找家人均一百以下的川菜馆",
     "expect": {"tools": ["meituan"], "args": {"meituan.task": {"contains": ["川菜", "100"]}}}},
    {"seat": "主驾", "text": "第二家",
     "expect": {"calls": [{"tool": "navigation", "command": "Navigation.SearchPoi",
                           "params": {"Keyword": {"equals_ref": "turn1.poi[1].name"}}}]}},
    {"seat": "主驾", "text": "算了还是点外卖吧帮我点他家的水煮鱼",
     "expect": {"tools": ["meituan", "meituan_place_order"], "confirm": true}}
  ]
}
```

- `tools`：本轮必须调用的工具集合（默认顺序无关，`ordered: true` 时要求顺序）；`[]` 表示应直接回答、不调工具；
- `calls`：Command tool 的期望写成 `{tool, command, params}`，例如 `{"tool": "climate", "command": "ACCtrl.SetTemperature", "params": {"Area": "主驾", "Number": "20"}}`；只判写到的参数（协议参数可空），Position 的等价写法（“所有”与不填）按协议默认值归一后再比；
- `not_tools`：不许调用的工具；
- `args`：参数断言，支持等于、包含（任一 / 全部）、数值范围、引用前面轮次的结果（`equals_ref`）；推理型 Agent 的 `task` 只断言关键信息是否写进去了；
- `confirm`：是否应出现确认；`status`：期望的协议状态码（如 `PrecondSpeedNotSupported`），用于前置条件场景。

### 12.2 判定

| 判定 | 规则 |
|---|---|
| 选对 | 实际调用的工具集合 ⊇ `tools` 且与 `not_tools` 无交集，`calls` 里的 tool 和指令名都出现；`tools` 为空时实际也没调工具。多余的查询类 tool（`vehicle_query`、`nav_query`、`contact_query`）不算错 |
| 填对 | 选对的前提下，`args` 和 `calls.params` 的每一条断言都成立；出现过 ParamError 记为填错，即使改正后成功 |
| 多轮整段完成 | 每一轮都选对、填对 |

每个场景跑 3 次，报告三次的均值和“三次都对”的比例，看稳定性。

### 12.3 场景来源和规模

| 集 | 来源 | 规模 |
|---|---|---|
| 单轮基础 | v6 文档“分流示例”、判据 v3.5 冒烟集 `docs/share/criteria_v3_smoke.txt`、`data/快思考测试集` 中的车控、媒体、导航、电话样例，带 domain / intent / slots 标注的按协议的 domain + intent → 指令映射生成期望；全部用无标点文本 | ~200 |
| 协议话术 | Command 协议每条指令的话术示例（约 700 句），去标点后自动生成期望，人工抽检 10%；M1 就生成（`scenarios/protocol.jsonl`），单独报告、不计入通过线 | ~700 |
| 难例 | 有依赖多任务、跨能力多任务、多轮指代、俗称、隐含车控（v6 文档示例表和测试方案里的） | ~40 |
| 多轮 | 第 10.2 节体验脚本的每一轮，加美团、任务大师、用车专家的追问 | ~40 段 |
| 权限、状态码、未上线能力 | 前置条件（行驶中、未上电、蓝牙断开、无配置）、需确认、黑区、违法有害、车外视觉 / 有声书 / 400 客服 | ~40 |

### 12.4 评测脚本

`python -m eval.run_eval --set scenarios/ --repeat 3`，输出 `runs/v7/report.md`：

- 按第 1 节通过线口径的结论（单轮基础 + 难例、多轮集），协议话术集单独一栏；
- 总体和按标签（业务 Agent、单轮 / 多轮、难例类型）的选对率、填对率、多轮整段完成率；
- 混淆表：期望调 A、实际调了 B 的次数，用来改工具描述；
- 参数错误清单：哪个工具哪个参数错得最多；
- 失败样例，链接到 trace，可以在体验页里回放。

## 15. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 工具多了以后选错率上升 | 选对率不达标 | 19 个 Command tool 加 4 个推理型共 23 个工具；描述写清边界、给反例；看混淆表合并或拆分工具；推理型 Agent 只注册已上线的 |
| 单个 tool 指令太多 | `system_settings`（127）、`system_apps`（115）里选错指令 | 描述按小类分组；混淆集中时拆成更细的 tool |
| 黑区、需确认清单未确认 | 演示时开放了不该开放的操作 | 清单先从严；车控、智驾负责人确认后再放开 |
| 协议命名不统一 | 大脑把 `KeyWord` 写成 `Keyword` 被判 ParamError | tool 描述里写明协议原样；问题清单提给协议负责人 |
| 推理型 Agent 的 `task` 写得不全 | 子 Agent 办错，参数断言不过 | 工具描述里列出 task 必须包含的信息；评测里单独统计 |
| 已上线 Agent 的接口没拿到 | 只能用模拟数据，体验和结论偏乐观 | 报告里分开写模拟和真实；接口拿到后补测 |
| 演示时模型偶发不稳定 | 现场体验打折 | 每个场景跑 3 次看稳定性；体验脚本提前回放，不稳定的轮次改提示词或换脚本 |
| 网络 | 开发环境访问不了 DeepSeek（skill 记录的云端环境限制） | 真实评测和演示在本机或 GitHub Actions 跑 |
| 仓库根 `agentscope/` 目录遮蔽 pip 包 | `import agentscope` 拿错 | 见第 2 节命名约定 |
