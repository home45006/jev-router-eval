- 版本：V1.3 · 2026-11-04（V1.3：模型定为 DeepSeek V4 Flash 非思考模式，不做模型对照，6.2 取消，时间并入提示词调优；写明通过线口径；协议话术集和评测脚本第一版提前到 M1，批量评测页挪到 M5；任务大师加“立即触发”；体验脚本 7 → 9 个；补齐设计里漏排的任务；V1.2：确定型业务 Agent 改为按 Command 协议封装的 19 个模拟 tool，M1 加 1 天，后续整体顺延 1 天；V1.1：目标收敛为“选对业务 Agent、填对参数”和智能交互体验，去掉时延和费用相关工作）
- 设计：`agentscope/原型详细设计-v7.md`（V1.3）；`agentscope/Command 协议 Tool 封装设计-v1.html`；架构：`docs/座舱 Agent 大脑架构-v7.html`
- 模型：大脑和子 Agent 都用 DeepSeek V4 Flash（`deepseek-flash`）非思考模式，不和其他模型或思考模式对照
- 周期：2026-11-05（周四）— 2026-12-02（周三），20 个工作日，按 1 名开发估算
- 终点：原型演示和评审会。用评测报告说明大脑选对、填对的水平，用体验脚本现场演示智能交互，决定 v7 是否进入正式开发

## 1. 原型目标

| 目标 | 怎么判 | 通过线 |
|---|---|---|
| 选对业务 Agent | 场景集，每轮实际调用的工具和期望一致；Command tool 要求 tool 和协议指令名都对 | 单轮 ≥ 95% |
| 填对参数 | 场景集，Command tool 按协议槽位逐项断言，推理型 Agent 断言 task 关键信息 | 单轮 ≥ 90% |
| 多轮里仍然选对、填对 | 多轮场景整段每轮都对 | ≥ 85% |
| 智能交互体验 | 9 个体验脚本能稳定演示；试用者按打分表打分 | 演示无翻车；试用反馈“像有智能”的占多数 |

**通过线口径**：选对、填对两项按“单轮基础 + 难例”两个集合计算，取 3 次回放的均值，同时报告“3 次都对”的比例；协议话术集是从协议示例自动生成的，比较好答，单独报告、不计入通过线；多轮按多轮集整段计算。

简单车控的时延和大模型开销不设目标、不做优化。

## 5. 风险和应对

| 风险 | 信号 | 应对 |
|---|---|---|
| 选对率、填对率不达标 | M1 末的小评测、M5 第一版报告 | 看 tool 级和指令级混淆表改描述和反例；混淆集中的 tool 拆分；评审顺延 2 天 |
| 大 tool 里选错指令 | `system_settings`（127 条）、`system_apps`（115 条）的指令级错误多 | 描述按小类分组；必要时拆成更细的 tool |
| 协议参数名写错 | ParamError 多，集中在 `KeyWord` / `Keyword` 这类 | tool 描述写明原样拼写；问题提给协议负责人 |
| 中间件返回 ASK 不触发确认 | M3 接线测试 | 需确认的指令拆到单独 tool，tool 级设 ASK |
| 推理型 Agent 的 `task` 写不全 | 参数断言里 task 类错误多 | 工具描述列出 task 必须包含的信息 |
| 体验脚本现场不稳定 | 同一脚本 3 次回放结果不一致 | 演示前回放；不稳定的轮次改提示词或换脚本（不靠换模型解决） |
| 美团等接口拿不到 | M2 开始时 | 用模拟数据推进，不阻塞；评审时说明结论的局限 |
| AgentScope 行为和文档不符 | 接线测试 | 以 2.0.9 源码为准；补进 `.claude/skills/agentscope-cockpit` 的速查表 |
| 计划没有缓冲 | 任一里程碑拖期超过半天 | 先砍体验页的可选项（浏览器语音输入和朗读、部件示意图的细节），不砍评测；仍不够时评审顺延到 12-04 |
